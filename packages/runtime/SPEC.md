# Runtime specification

## Optional topical context assembly

`context` accepts `ContextOptions.ranking` and the Door accepts `params.ranking`: `native` (default) preserves the existing procedure-first order; `topical` reserves all applicable blocking governance first, then orders other admitted candidates by the existing scoped text-search score, using native entry order for ties. Packets identify this opt-in mode with `ranking: "topical"`. It changes neither candidate eligibility, scope, coordinate validation, blocker overflow refusal nor exclusive execution selection. It is a retrieval option, not a semantic accuracy guarantee.

## P3 managed publication contract

`preparePublication` and `inspectPublication` own the local create-only draft primitive; the upper composition package supplies engine authorization and exact review/provenance. Outputs are bounded UTF-8 files under one host-selected `.ia/work/generated/<id>` directory, never `.ia/src`. Portable paths, case-folded collisions, reserved `result.json`, parent/leaf aliases and unsupported filesystems refuse. The first qualified profile is a local Windows NTFS volume, verified through the installed fixed volume probe; other filesystems/platforms refuse until separately qualified.

P4 exports the same read-only `qualifyPublicationRoot` check so a host can reject an unsupported or aliased root before starting an artifact task. It returns the canonical supported root without creating draft, lock or session files. Publication and inspection repeat this check at their actual boundary; host qualification is not a reusable grant.

A separate per-destination SQLite transaction lock is held from staging through publication or inspection, across sessions. No PID/time-based lock stealing. Staged files and metadata are flushed, the destination is claimed with exclusive directory creation, files are linked create-only, and `result.json` is linked last as the completion marker. Existing destinations are never replaced, including empty directories. Inspecting under the same lock establishes quiescence for cooperating publishers, then checks the exact manifest bytes, complete file inventory and every content digest. Absent, applied, partial and conflicting/unknown results remain distinct. Partial outputs are retained for remediation; automatic repair/overwrite and abandoned-stage garbage collection are outside this packet.

The host owns the workspace and managed area; other users cannot mutate ancestors, lock databases or draft files. This is protection against competing cooperating processes and process death, not a sandbox against malicious same-user filesystem mutation. File flushes and process-kill tests do not establish hardware power-loss durability. The shared primitive is also consumed by the existing Stage E publisher while preserving its output paths and result format.

P2 candidate admission: `validateCandidate(input, candidate, scope)` validates an exact source-set/base vector, intended system/discriminator, bounded UTF-8 files with SHA-256 digests and cited source ranges. The trusted host supplies only the source closure disclosed to this run, permitted systems and exact candidate paths. Runtime builds admission views from those bytes without filesystem reads/writes, refuses authority changes, existing paths, shadowing, bad references and invalid citations, and returns bounded diagnostic codes with candidate-only locations. This is a read, distinct from generation, managed publication and source application. The upper composition package exposes its engine adapter; foundation packages gain no reverse dependency.

Editor extension contract (2026-09-18): public `/editor` composes language projections and database memory readers. It owns disposable per-root owner sessions, monotonic generations, saved/view revisions, occurrence-aware action handles, bounded graph/inspection projections and candidate validation. It exposes no cloud credentials or workspace execution. Host foundation imports go through this facade; semantic interpretation, discovery and admission remain with their existing owners.

Remote authoring client contract: `/authoring` owns the portable version-1 request, proposal, capabilities, event and chat schemas, their digest and limit checks, and a bounded HTTPS client, with loopback HTTP for development, that refuses redirects and requests outside its configured origin. A separately configured service implements authentication, authorization, persisted runs, events, cancellation and model execution. The extension owns credential storage, disclosure, review and local file effects. This package contains the client contract and transport; it does not include a hosted service or model credentials.

Platform M1 transport refinement: failed JSON responses preserve a string service `code`, or the standard OAuth string `error` when `code` is absent, as `AuthoringError.code`; status remains separate. OAuth `error_description` is not copied into error messages. Credential invalidation belongs to the authenticated client and requires a conclusive refresh-grant error, not an arbitrary transport failure.

Implementation contract for runtime/hosts plan, shared graph sections6-12/15 and systems section12. Depends only on language, graph and db. Implemented through runtime plan Task5, including coordinates, context/select, the scoped door and pure steward evaluation. Task paragraphs below are historical delivery evidence; their next-task statements do not describe the current implementation.

R01. Request coordinates use graph's closed axes and canonical values. Runtime accepts text, explicit axes, optional subject/follow and a database within token. Validate declared/profile/classifier values; never silently ignore an unknown axis. prepareCoordinate returns values plus declared/profile/derived/absent for every ConditionAxis and native shape focus lists. Declared values win over a supplied profile, which wins over derivation; phase and primitive must be declared by the request and cannot come from profile or classifier. Derive only shape and category; shape-row kind/lane/predicate arrays remain explicit focus hints, not scalar selector constraints. Profile cannot impersonate declared phase/primitive. Category gloss fields on records are never read for matching.

R02. classify(text) is a deterministic replaceable keyword seam over request prose only. Port the donor matrix/classify signals, select greatest signal count then native SHAPE_ROWS tiePrecedence, use context for no signal. Unknown custom output is COORDINATE-VALUE-UNKNOWN, not a fallback. A custom classifier is called only when shape is absent from request/profile. Mark supplied shape declared/profile and inferred shape derived. Explicit primitive and move participate unchanged in graph selector matching.

R03. context(handle, request, budget, options?) derives a phase-bound child of request.within and reads only through that token. Missing declared phase or primitive returns coordinate-incomplete; source token failures retain database codes. No hidden graph/registry/diagnostics are fetched for ranking. Packet records revision, child scope, coordinate provenance, included/omitted entries, followed/gated/dangling edges and measured limits. All public products are immutable. The opaque child token may differ between equivalent calls; semantic payload/order is deterministic.

R04. Admission steps are exact cell, separate primary fallback, applicable governance, satisfied selector, explicit subject/identity mention, then scoped BM25. Use graph.cell/selectors/variants/conditionHolds/effectiveSeverity and db.search/traverse. Selector disqualification excludes all ordinary retrieval and is reported with contradictory terms; blocking governance is evaluated only when its selectors admit the coordinate. A partial uncontradicted selector group stays eligible for topical/subject retrieval but cannot establish step4. Do not infer selectors from gloss fields. A node contributes its selected cell once at step1/2; governance obligations may contribute an additional step3 entry. Steps4-6 never dump the remaining body of a node already delivered at an earlier step.

R05. Steps1/2 order by descending band then identity; steps4-6 by selector specificity plus normalized scoped BM25, then descending band and identity. Step3 orders by band/identity. Selected governance text includes only applicable maximum-specificity clauses, with effective severity and each clause's key/condition/source span retained. No losing clause is delivered through generic body rendering. Generic bodies use already decoded compiled values and applicable semantic products; no consumer parses authored when words. Preserve source citations for every delivered cell/clause/body. Cell addresses use the language's phase/Primitive fragments. Governance and generic entries use the record identity with separate clause metadata, not invented resolvable fragments.

R06. A subject is a canonical identity, sigil ref or unambiguous exact name in the allowed pool. Request prose mentions may be typed sigils, canonical four-slot identities or kind/name forms; resolve against allowed records with exact cardinality, never first-match. Unresolved/ambiguous subjects/mentions produce attributable omission observations, not hidden-corpus queries. Request mention recognition is not IA source parsing. An explicit subject cell/requirement fragment is validated against the admitted node; missing fragments refuse the requested address.

R07. Budget tokens measure the sum of delivered text using an injectable named count(text); a cell entry's purpose (its record's says and answers) is delivered text only when the caller asks for it, and is then counted with the cell; default byte-estimate is ceil(UTF8 bytes/4), minimum1 for nonempty text, zero for empty. Budget records count distinct identities, not entries. Limits expose budgets, used text tokens, identity count, estimator name and serialized-envelope byte estimate separately. These are text estimates; host/model wrappers own their extra overhead. Negative/noninteger budgets or invalid estimator counts are IA-RUNTIME-BUDGET-INVALID. Reserve every applicable governance entry whose effective severity is blocking before optional admission. If blockers alone overflow, return IA-GRAPH-BUDGET-BLOCKING-OVERFLOW with minimum required budgets and the smallest number of blocking identities whose removal would fit; calculate that suggestion by descending per-identity token total, identity tie-break. This suggestion grants no permission to drop obligations. Fill remaining budget greedily in semantic order; omitted entries name budget as the cause. Display included entries in semantic order after reservation.

R08. Follow from included identities at depth1, scoped by the same token and request coordinate. Explicit follow overrides native shape predicate focus, including an empty list. Convert each native predicate focus to its language-table active verb phrase; do not invent suffixes. Return graph's followed/gated/dangling products with deduplication and total order. Traversed neighbours are evidence, not automatically delivered text or execution grants.

R09. select uses the same unbudgeted steps and scores over an explicit caller-supplied candidate identity set intersected with the scope. Phase and primitive are always required; caller may additionally require closed axes. A candidate whose nonempty selector groups remain partial with no fully matched group also requires its missing, uncontradicted selector axes before exclusive selection. Neutral topical eligibility cannot grant execution selection. Absence produces coordinate-incomplete; no eligible result no-candidate; equal leading step/score/band deny-wins-tie. Lower-step or lower-score ties do not block a stronger winner. Return identity/address plus revision/scope and evidence. A selected binding does not execute anything or confer permission.

R10. The door is a structured adapter over scope/context/select/get/search/traverse and privileged local report inspection. Hosts validate requests, hold the issuer Handle and root boundary, and return named errors from their owning namespace. Unknown operation/malformed request is IA-RUNTIME-REQUEST-INVALID. No source writes, model calls, sessions or capability dispatch occur. The implemented MCP/CLI hosts own transport policy; agent-runner session/model dispatch is a separate native-package consumer, not an added door operation.

R11. Runtime exports its refusal inventory, including the shared specification's IA-GRAPH-BUDGET-BLOCKING-OVERFLOW and coordinate-incomplete/deny-wins-tie/no-candidate escalation results. Every outcome gets native fixture success/refusal evidence. Full loop acceptance includes database admission/schema restoration/cache/identity, exact and primary cells, advisory law variants and conditional inverse edges, declared category, gloss independence, selection ties/incomplete coordinate, coverage/fragments and the separately owned steward hook. Entry contract (2026-09-24): `/entry` exports `isEntry(argv1, moduleUrl)`, which a package binary calls with `process.argv[1]` and `import.meta.url` to decide whether it is the process entry. The invoked path is compared first and real paths only when it misses, because npm's `.bin` entries, global installs and pnpm's store links reach an entry through a link while Node loads it from its real path. A path that names no file (missing, through a file, or with a name too long) is not the entry; any other failure to resolve one throws rather than answering "not the entry". An argument Node resolves further, such as an extensionless path or a package directory, names no file itself, so a binary started that way does not recognise itself as the entry and exits 0 having done nothing. It imports only Node built-ins, and the root index re-exports it. `@inventarch/folio`, which may import only `@inventarch/language`, repeats it.

Machine protocol description (2026-09-29, spec-0012): `MACHINE_PROTOCOL` (`src/machine-protocol.ts`, exported from the package root) describes the nine Door operations. For each it records a summary, a description, the parameter JSON Schema, the result, the refusals with their next action, an example that returns `ok: true` on `packages/compliance/fixtures/loop`, and the MCP tool that serves it. CLI help and the MCP door's `tools/list` project it, and in this source tree so does the generated `docs/reference/cli/machine-protocol.md`, which the public candidate does not carry. It is data and never validates; the Door keeps its own checks. `tests/select-door.test.ts` fails when the table's operation names or parameter keys, nested ones included, differ from the ones the Door names when it refuses an unknown key.

Body reader (2026-10-07): `src/locator.ts`, exported from the package root, publishes `parseLocator(text)`, `readBody(handle, locator, {within})` and `locateRecord(handle, locator, {within})`. A locator is a canonical identity, `identity#phase/Primitive` (a cell), `identity#REQ-…` (a requirement, in the language's requirement-id form) or `path:line` (a root-relative source path, compared in forward-slash spelling with its `.`, `..` and empty segments resolved lexically, and a line from 1; any text ending in `:<line>` is one, so a `#` before it belongs to the path, since identities and fragments hold no colon); anything else is IA-RUNTIME-REQUEST-INVALID. `readBody` reads only through the handle and the optional scope token and returns an immutable `{identity, fragment, body, digest, source}`. The body is the record's own text: its `says` (a record without one, such as a `@system`, gives its head `describes`), the cell's text or the requirement's text; a line names the innermost admitted record whose source lines hold it (smallest span, then latest start), read as its identity is. `fragment` is the cell address or requirement id, or null; `digest` is the record's graph G13 per-record digest; `source` is `record`. Nothing to read behind a locator (no such record in scope, no such cell, requirement or source line, or a record with no body text, such as a `@schema`) throws IA-DB-SOURCE-UNAVAILABLE; `locateRecord` returns the admitted record a locator resolves to (the identity's record for a cell or requirement, the innermost holder for a line) whether or not it has a body, or undefined, so a caller can name it when there is nothing to read; a token's own failures keep their database codes, IA-DB-OUT-OF-SCOPE included. It reads no file: the document a record's source locator names (a work item's `source`, an authoring guide's `reference.document`, a template's `resource`) is not read here, and `source` is the discriminant reserved for a reader of it. It is not a Door operation; the nine routes are unchanged.

Scope key (2026-10-07): `src/scope-key.ts`, exported from the package root, publishes the scope key K = (seat, shape, phase, depth, budget, word) a position request asks with, and `normalizeScopeKey(key)`, which validates and completes one without reading a record and returns an immutable `{seat, shape, phase, primitive, depth, budget, word, k0, sources, coordinate}`. An empty key is `K0`: the workspace seat (`seat: null`), the `context` shape, the `orient` phase, depth 0, budget 0 and no word; `k0` is true for every key whose value is K0, however it is spelled. A non-empty key gets depth 1 and budget 16 when it omits them (`SCOPE_KEY_DEFAULTS`). Depth, the hops from the seeds, is an integer from 0 to 2, and budget, the loaded records beyond the seat, an integer from 0 to 64 (`SCOPE_KEY_CAPS`); budget counts records, not tokens, is not the context route's `Budget`, and rules whose effective severity is blocking are not counted against it. The primitive is the shape row's `primitive`, and an omitted phase is that primitive's anchor phase (`PRIMITIVE_ANCHORS`: context orient, governance plan, execution act, sequence plan, learning learn), so a shape and a phase alone give the complete `coordinate` {shape, phase, primitive}. `sources` marks every part and the primitive `declared`, `derived` (from another part) or `default`. The seat (a path or a record identity) and the word are carried as non-empty text for seeding to resolve. Unknown parts, values outside the caps and malformed seats or words are IA-RUNTIME-REQUEST-INVALID; an unknown shape or phase is IA-GRAPH-COORDINATE-VALUE-UNKNOWN. `SCOPE_BODY_LIMITS` (48 pointers before the rest is told as tallies, 4 cells per record) are constants of every body, not parts of the key. The primitive is derived only here: R01, R03 and R09 are unchanged, so `prepareCoordinate`, `context` and `select` still require a declared phase and primitive and refuse coordinate-incomplete without them. It is not a Door operation; the nine routes are unchanged.

Seeding (2026-10-07): `src/seed.ts`, exported from the package root, publishes `seatOf(handle, within, key)` and `seed(handle, within, key)` over a normalized scope key. Records, rows and membership are read through the `within` scope token; the only other reads are the handle's report, for consent refusals at loaded records, and the check that a seat naming no record in the scope names none outside it either. The seat is the workspace seat when the key has none (the seat the empty path resolves to under the database seat rule; `identity: null` is the synthetic workspace closure), an admitted record when the key names one (`workspace`, `system` or `record`), and otherwise a path, a `location` seat resolved by the database's `resolveSeat`; a seat naming a record outside the scope is IA-DB-OUT-OF-SCOPE and an unsafe path IA-DB-PATH-UNSAFE. Every seat names its `home`, the @workspace whose closure the seeding stays inside; a record whose membership seat is a @system (an adopted record in a system folder, or an adopted @system, which seats itself) belongs to the closure of that system's own workspace, or of the workspace seat when the system seats itself or lies outside the scope. C0 is composed one level from the seat at no depth cost: field references in both directions (`field`), the records captured with a workspace seat (`capture`), the records of the words a system seat registers (`word`), and the records declared at a location seat's path and claiming it (`declared`, `claimant`); a key's word keeps only records of that word. The seeds are the C0 records whose kind is in the shape's kind focus or whose lane is in its lane focus. Hops follow derived directed-view rows whose predicate is in the shape's predicate focus, in either direction and in either spelling, up to the key's depth; a field reference, a dangling row and an unconsented edge are never followed, and a reached record is loaded whatever its kind. Runtime-band records are never read. Open-band records are never composed, seeded or entered, and neither is another @workspace or a record captured in one: both are listed as `held`, with the hop and the row or composition that met them. Ranked records are ordered by (priming index ascending, band descending, hop ascending, severity in the native order, identity) under governance, where the priming index is the lowest index in the shape's priming list among the record's consented rows (none sorts after every index), and by (band descending, hop ascending, lane-focus index, identity) under every other shape. The budget counts loaded records beyond the seat; governance whose effective severity is blocking is loaded outside the budget and never refused, and `truncated` counts the ranked records the budget cut. The phase never changes what is loaded. `unknowns` lists, for each loaded record, the rows it declares whose target does not resolve (`dangling`) and its edges refused for consent (`unconsented`, from the IA-GRAPH-EDGE-UNCONSENTED finding at its source). The result is immutable and carries the admitted revision and the key's value without per-part sources, never a scope token or an absolute path, so equal key values over one revision seed byte-identical results. Pointers, tallies, cells and the rendered body are not part of seeding, and it is not a Door operation; the nine routes are unchanged.

## Neutral authoring execution boundary

`@inventarch/runtime/authoring-execution` owns shared authoring operation context/errors, input and artifact helpers, and guarded dispatch. A trusted host supplies its fixed catalog; no decoded request may supply handlers or widen effects. Dispatch preserves exact admitted operation/source identity, declared handler/input/output/effects, steward authorization, safe unique artifact paths, read-only output refusal and final source freshness. This factors the existing tools/systems mechanics without a private catalog, architecture packet, quality codec or queue dependency. Existing tools imports remain compatibility wrappers. This API does not authenticate arbitrary catalogs or authorize filesystem publication; each host owns its selected catalog and grants.

This boundary also owns the neutral repository inventory helpers used by existing documentation and private review consumers. `gitFiles` executes only the fixed local `git ls-files --cached --others --exclude-standard -z` query, deduplicates/sorts the result and refuses subprocess/output limits (10 seconds,16MiB). `ownerOf` preserves the existing root/package/app/tool/example/distribution/native owner path mapping exactly; it selects no catalogue, executable, quality policy or queue. Tool imports remain compatibility exports. Consumer source capture must still validate file bytes, aliases and scope; a path listing is not source admission or authority. Status (LKI-01, implemented at 22cc1d8d, not qualified): `ownerOf` names its root-owned top-level directories by stem, so no runtime source or test carries the CI-configuration directory as a path segment and the cache-safety invariant in `tools/testing/inventory.test.ts` (only tools tasks read CI configuration) holds again; the mapping and both exports are unchanged. Evidence: `tools/testing/inventory.test.ts` failed at 3f0e9853 (`runtime:test` classified as a CI-configuration reader) and passes at 22cc1d8d.

Mandate authority (2026-10-06, position-and-projection items 2c and 13): `src/mandate-modes.ts`, exported from the package root, publishes `MOVES` (the five kernel moves in kernel order), the frozen `MODE_MOVES` table (read→Observation, validate→Verification, author→Synthesis, effect→Execution, re-seat→Delegation), `mandateAuthorityOf(record)`, which reads a compiled `@mandate`'s `authority` section (participant, moves, scope, excluded-words, covers) and refuses a non-mandate or a malformed field with IA-RUNTIME-REQUEST-INVALID, and `mandateRefusal(mandate, mode, words)`, which returns undefined when the mandate permits the mode for the words and otherwise `{code, message, next}`: IA-RUNTIME-MANDATE-MOVE when the mode's move is not among the declared moves, IA-RUNTIME-MANDATE-WORD when a word is excluded, and `next` exactly one catalog command, `ia inspect <mandate identity> --edges both`. A mandate without `authority.moves` restricts no move; a declared list admits only the moves it lists and must name at least one (an authored `moves []` admits structurally but is IA-RUNTIME-REQUEST-INVALID here, never a lockout); excluded words are refused whatever the moves; the move is judged before the words. Both codes are registered in RUNTIME_CODES and covered by the compliance runtime fixtures over the conformance sample-mandate. No CLI command consults a mandate yet: the authoring verbs land in a later milestone, and a mandate adds closed restrictions only; it never grants host permissions.
