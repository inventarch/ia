# Runtime specification

## Optional topical context assembly

`context` accepts `ContextOptions.ranking` and the Door accepts `params.ranking`: `native` (default) preserves the existing procedure-first order; `topical` reserves all applicable blocking governance first, then orders other admitted candidates by the existing scoped text-search score, using native entry order for ties. Packets identify this opt-in mode with `ranking: "topical"`. It changes neither candidate eligibility, scope, coordinate validation, blocker overflow refusal nor exclusive execution selection. It is a retrieval option, not a semantic accuracy guarantee.

## P3 managed publication contract

`preparePublication` and `inspectPublication` own the local create-only draft primitive; the upper composition package supplies engine authorization and exact review/provenance. Outputs are bounded UTF-8 files under one host-selected `.ia/work/generated/<id>` directory, never `.ia/src`. Portable paths, case-folded collisions, reserved `result.json`, parent/leaf aliases and unsupported filesystems refuse. The first qualified profile is a local Windows NTFS volume, verified through the installed fixed volume probe; other filesystems/platforms refuse until separately qualified.

P4 exports the same read-only `qualifyPublicationRoot` check so a host can reject an unsupported or aliased root before starting an artifact task. It returns the canonical supported root without creating draft, lock or session files. Publication and inspection repeat this check at their actual boundary; host qualification is not a reusable grant.

A separate per-destination SQLite transaction lock is held from staging through publication or inspection, across sessions. No PID/time-based lock stealing. Staged files and metadata are flushed, the destination is claimed with exclusive directory creation, files are linked create-only, and `result.json` is linked last as the completion marker. Existing destinations are never replaced, including empty directories. Inspecting under the same lock establishes quiescence for cooperating publishers, then checks the exact manifest bytes, complete file inventory and every content digest. Absent, applied, partial and conflicting/unknown results remain distinct. Partial outputs are retained for remediation; automatic repair/overwrite and abandoned-stage garbage collection are outside this packet.

The host owns the workspace and managed area; other users cannot mutate ancestors, lock databases or draft files. This is protection against competing cooperating processes and process death, not a sandbox against malicious same-user filesystem mutation. File flushes and process-kill tests do not establish hardware power-loss durability. The shared primitive is also consumed by the existing Stage E publisher while preserving its output paths and result format.

P2 candidate admission: `validateCandidate(input, candidate, scope)` validates an exact source-set/base vector, intended system/discriminator, bounded UTF-8 files with SHA-256 digests and cited source ranges. The trusted host supplies only the source closure disclosed to this run, permitted systems and exact candidate paths. Runtime builds admission views from those bytes without filesystem reads/writes, refuses authority changes, existing paths, shadowing, bad references and invalid citations, and returns bounded diagnostic codes with candidate-only locations. This is a read, distinct from generation, managed publication and source application. The upper composition package exposes its engine adapter; foundation packages gain no reverse dependency.

Editor extension contract (2026-09-18): public `/editor` composes language projections and database memory readers. It owns disposable per-root owner sessions, monotonic generations, saved/view revisions, occurrence-aware action handles, bounded graph/inspection projections and candidate validation. It exposes no cloud credentials or workspace execution. Host foundation imports go through this facade; semantic interpretation, discovery and admission remain with their existing owners.

Remote authoring client contract: `/authoring` owns the portable version-1 request, proposal, capabilities, event and chat schemas, their digest and limit checks, and a bounded HTTPS client, with loopback HTTP for development, that refuses redirects and requests outside its configured origin. A separately configured service implements authentication, authorization, persisted runs, events, cancellation and model execution. The extension owns credential storage, disclosure, review and local file effects. This package contains the client contract and transport; it does not include a hosted service or model credentials.

Platform M1 transport refinement: failed JSON responses preserve a string service `code`, or the standard OAuth string `error` when `code` is absent, as `AuthoringError.code`; status remains separate. OAuth `error_description` is not copied into error messages. Credential invalidation belongs to the authenticated client and requires a conclusive refresh-grant error, not an arbitrary transport failure.

R01. Request coordinates use graph's closed axes and canonical values. Runtime accepts text, explicit axes, optional subject/follow and a database within token. Validate declared/profile/classifier values; never silently ignore an unknown axis. prepareCoordinate returns values plus declared/profile/derived/absent for every ConditionAxis and native shape focus lists. Declared values win over a supplied profile, which wins over derivation; phase and primitive must be declared by the request and cannot come from profile or classifier. Derive only shape and category; shape-row kind/lane/predicate arrays remain explicit focus hints, not scalar selector constraints. Profile cannot impersonate declared phase/primitive. Category gloss fields on records are never read for matching. A scope key (R14) is the one exception, on its own path only: scopeCoordinate declares the key's shape and phase and derives category and the primitive, SHAPE_ROWS[shape].primitive, marked derived, so a key with a shape and a phase is never coordinate-incomplete. prepareCoordinate is unchanged and leaves an undeclared primitive absent, and every version 1 context and select request without one is still refused as coordinate-incomplete.

R02. classify(text) is a deterministic replaceable keyword seam over request prose only. Port the donor matrix/classify signals, select greatest signal count then native SHAPE_ROWS tiePrecedence, use context for no signal. Unknown custom output is COORDINATE-VALUE-UNKNOWN, not a fallback. A custom classifier is called only when shape is absent from request/profile. Mark supplied shape declared/profile and inferred shape derived. Explicit primitive and move participate unchanged in graph selector matching.

R03. context(handle, request, budget, options?) derives a phase-bound child of request.within and reads only through that token. Missing declared phase or primitive returns coordinate-incomplete; source token failures retain database codes. No hidden graph/registry/diagnostics are fetched for ranking. Packet records revision, child scope, coordinate provenance, included/omitted entries, followed/gated/dangling edges and measured limits. All public products are immutable. The opaque child token may differ between equivalent calls; semantic payload/order is deterministic.

R04. Admission steps are exact cell, separate primary fallback, applicable governance, satisfied selector, explicit subject/identity mention, then scoped BM25. Use graph.cell/selectors/variants/conditionHolds/effectiveSeverity and db.search/traverse. Selector disqualification excludes all ordinary retrieval and is reported with contradictory terms; blocking governance is evaluated only when its selectors admit the coordinate. A partial uncontradicted selector group stays eligible for topical/subject retrieval but cannot establish step4. Do not infer selectors from gloss fields. A node contributes its selected cell once at step1/2; governance obligations may contribute an additional step3 entry. Steps4-6 never dump the remaining body of a node already delivered at an earlier step.

R05. Steps1/2 order by descending band then identity; steps4-6 by selector specificity plus normalized scoped BM25, then descending band and identity. Step3 orders by band/identity. Selected governance text includes only applicable maximum-specificity clauses, with effective severity and each clause's key/condition/source span retained. No losing clause is delivered through generic body rendering. Generic bodies use already decoded compiled values and applicable semantic products; no consumer parses authored when words. Preserve source citations for every delivered cell/clause/body. Cell addresses use the language's phase/Primitive fragments. Governance and generic entries use the record identity with separate clause metadata, not invented resolvable fragments.

R06. A subject is a canonical identity, sigil ref or unambiguous exact name in the allowed pool. Request prose mentions may be typed sigils, canonical four-slot identities or kind/name forms; resolve against allowed records with exact cardinality, never first-match. Unresolved/ambiguous subjects/mentions produce attributable omission observations, not hidden-corpus queries. Request mention recognition is not IA source parsing. An explicit subject cell/requirement fragment is validated against the admitted node; missing fragments refuse the requested address.

R07. Budget tokens measure the sum of delivered text using an injectable named count(text); a cell entry's purpose (its record's says and answers) is delivered text only when the caller asks for it, and is then counted with the cell; default byte-estimate is ceil(UTF8 bytes/4), minimum1 for nonempty text, zero for empty. Budget records count distinct identities, not entries. Limits expose budgets, used text tokens, identity count, estimator name and serialized-envelope byte estimate separately. These are text estimates; host/model wrappers own their extra overhead. Negative/noninteger budgets or invalid estimator counts are IA-RUNTIME-BUDGET-INVALID. Reserve every applicable governance entry whose effective severity is blocking before optional admission. If blockers alone overflow, return IA-GRAPH-BUDGET-BLOCKING-OVERFLOW with minimum required budgets and the smallest number of blocking identities whose removal would fit; calculate that suggestion by descending per-identity token total, identity tie-break. This suggestion grants no permission to drop obligations. Fill remaining budget greedily in semantic order; omitted entries name budget as the cause. Display included entries in semantic order after reservation. This is the budget of `context` and the version 1 Door alone. A scope key's `budget` (R14) is a different bound, set with its `depth` by decision scope-key-caps: n counts entries a body may load beyond the seat, 0..64 and 16 unless the key names it, blocking entries are reserved outside it and never counted against it, and n = 0 loads none, so K0 (budget 0) is pointers only; depth caps hops at 0..2, 1 unless named and 0 in K0. This release validates both caps and applies the defaults (normalizeScopeKey) and assembles no body for a key.

R08. Follow from included identities at depth1, scoped by the same token and request coordinate. Explicit follow overrides native shape predicate focus, including an empty list. Convert each native predicate focus to its language-table active verb phrase; do not invent suffixes. Return graph's followed/gated/dangling products with deduplication and total order. Traversed neighbours are evidence, not automatically delivered text or execution grants.

R09. select uses the same unbudgeted steps and scores over an explicit caller-supplied candidate identity set intersected with the scope. Phase and primitive are always required; caller may additionally require closed axes. A candidate whose nonempty selector groups remain partial with no fully matched group also requires its missing, uncontradicted selector axes before exclusive selection. Neutral topical eligibility cannot grant execution selection. Absence produces coordinate-incomplete; no eligible result no-candidate; equal leading step/score/band deny-wins-tie. Lower-step or lower-score ties do not block a stronger winner. Return identity/address plus revision/scope and evidence. A selected binding does not execute anything or confer permission.

R14. Scope key (position-and-projection §1 and item 10; decisions scope-key-caps and scope-verb-dispatch). `src/scope-key.ts` holds it: the package root exports `K0`, `SCOPE_KEY_CAPS`, `normalizeScopeKey` and `resolveScopeKey` with the `ScopeKey`, `ResolvedSeat` and `ResolvedScopeKey` types, and the `./internal/scope-key` subpath carries the module; `scopeCoordinate` (R01) is in `src/coordinate.ts`, on the `./internal/coordinate` subpath only. `ScopeKey` is K = (seat, shape, phase, depth, budget, word): `shape` one of the five SHAPE_ROWS shapes, `phase` one of the four phases, `depth` an integer in 0..2, `budget` an integer in 0..64 and `word` optional; `SCOPE_KEY_CAPS` exports the two caps, and `K0` is the frozen key (no seat, context, orient, 0, 0, no word). Three seat notions are kept apart, each named once here. The key's `seat` is what a caller names: absent for the repository's own `@workspace`, a record identity, or `{path}` for a location. The resolved seat (`ResolvedSeat`) is what that names once read through the scope: `{kind, identity?, path?, unknown?}`, kind `workspace` for no seat (identity the repository's `@workspace`), `record` for an identity (identity that record) and `location` for a path (path its canonical workspace-relative path; a location is not a record and has no identity). The database's `SeatResolution.seat` (db D02b) is the record a path is declared at, a `@system` or `@workspace`; it stays in the result's `resolution` with the rule `by` and the path's claimants, and is never a location's resolved seat. `normalizeScopeKey(partial?)` completes a partial key with design §1's defaults, the one place every host applies them: a partial that names no part (a part whose value is undefined is not named) is K0; otherwise `shape` defaults to context, `phase` to the anchor phase of the shape's primitive, PRIMITIVE_ANCHORS[SHAPE_ROWS[shape].primitive] (context orient, governance plan, execution act, sequence plan, learning learn), `depth` to 1 and `budget` to 16, and a seat or word stays absent unless named. It reads nothing, so it checks the key's form and leaves the word and the seat to resolution. `resolveScopeKey(handle, within, key)` requires a scope token like every runtime read, checks a complete key and returns a frozen `{key, seat, resolution?, coordinate}`: `key` copies the validated parts in K order, a location as the canonical path it resolved to, so a key never carries the root; `seat` is the resolved seat; `resolution` is the database's resolution of the repository root `''` or of the path, for a workspace or location seat; and `coordinate` is scopeCoordinate's (R01), shape and phase declared, category and primitive derived. Every key refusal is IA-RUNTIME-REQUEST-INVALID naming the closed set or bound: an unknown part (a key never declares a primitive), a shape or phase outside its closed set, a depth or budget outside its cap or not an integer, a seat that is neither an identity nor `{path}`, a word the read's view does not register for its admitted systems (db D09a `words`), the refusal listing those it does, an identity that is not an admitted record in the scope, and a path outside the workspace root or escaping it. The key's parts, closed sets, caps and seat form are checked before any read, so a key malformed in them is refused whatever the token. An absolute path reads as the path from the handle's root that Node's `path.relative` gives (on Windows without case, with either separator), as `ia read` reads the path of a `<path>:<line>` locator inside the root, and the root itself, however it is spelled, as the location `''` that `.` also names (a locator, having no line in a directory, leaves the root as given); an absolute path on another drive has no path from the root and is refused. The path, so read or relative as given, goes to the database's `resolveSeat` (db D02b), which canonicalises it segment by segment and names one that escapes the workspace `outside`, refused here: a `..` segment escapes, while an in-root name that only begins with `..`, such as `..cache`, is inside the root whichever way it is spelled (`ia read`'s rewrite, a string-prefix test, leaves such an absolute locator as given). No seat takes the seat the database resolves for `''`: the `@workspace` declaring a `sources` root of the whole repository, else the repository's own `@workspace` as D02b decides it. When no admitted record in the scope is declared at a workspace or location seat, the resolved seat names `unknown: 'undeclared'`, and a workspace seat then has no identity: K0 is the empty composition with the unknown named, never a refusal (position-and-projection row 17). Database token failures (SCOPE-UNAVAILABLE, STALE, CLOSED) keep their IA-DB codes on every read the resolution makes: the word's, the identity's and the path's. This release types, completes, validates and resolves the key only. It assembles no body (seeding, pointers to 48 then tallies, the word's restriction of seeds and tallies, blockers reserved outside the budget), no host note and no Door operation; the nine version 1 Door routes, `context` and `select` included, and `ia scope` neither read nor accept a key, and the consumer verb will be `ia position`. `tests/scope-key.test.ts` pins the caps and K0; the defaults, an empty partial being K0 and every shape's anchor phase; a key naming only a shape resolved, and depth 3 and budget 65 refused; a key completed from shape and phase alone for every shape and phase; the unchanged version 1 refusal bytes of a context or select request that declares only shape and phase; the closed sets, caps and seat form refused by both functions, and the key's form refused before a forged token is read; the token on every seat form and the word, a forged, stale or closed one keeping its database code; the registered word checked in the scope's own view; each seat form and a location pruned by a narrower scope; absolute paths inside the root, in native, forward and mixed separators (and on Windows with the drive letter in either case), read as the relative path, the root in every spelling as the location `''`, an in-root name beginning with `..` read alike in both spellings, and absolute paths outside the root (a sibling whose name extends the root's among them), escaping paths and another drive refused; K0 seated by a workspace that declares the whole repository as a root; and K0 with the repository workspace undecided.

Entry contract (2026-09-24): `/entry` exports `isEntry(argv1, moduleUrl)`, which a package binary calls with `process.argv[1]` and `import.meta.url` to decide whether it is the process entry. The invoked path is compared first and real paths only when it misses, because npm's `.bin` entries, global installs and pnpm's store links reach an entry through a link while Node loads it from its real path. A path that names no file (missing, through a file, or with a name too long) is not the entry; any other failure to resolve one throws rather than answering "not the entry". An argument Node resolves further, such as an extensionless path or a package directory, names no file itself, so a binary started that way does not recognise itself as the entry and exits 0 having done nothing. It imports only Node built-ins, and the root index re-exports it. `@inventarch/folio`, which may import only `@inventarch/language`, repeats it.

## Neutral authoring execution boundary

`@inventarch/runtime/authoring-execution` owns shared authoring operation context/errors, input and artifact helpers, and guarded dispatch. A trusted host supplies its fixed catalog; no decoded request may supply handlers or widen effects. Dispatch preserves exact admitted operation/source identity, declared handler/input/output/effects, steward authorization, safe unique artifact paths, read-only output refusal and final source freshness. This factors the existing tools/systems mechanics without a private catalog, architecture packet, quality codec or queue dependency. Existing tools imports remain compatibility wrappers. This API does not authenticate arbitrary catalogs or authorize filesystem publication; each host owns its selected catalog and grants.

This boundary also owns the neutral repository inventory helpers used by existing documentation and private review consumers. `gitFiles` executes only the fixed local `git ls-files --cached --others --exclude-standard -z` query, deduplicates/sorts the result and refuses subprocess/output limits (10 seconds,16MiB). `ownerOf` preserves the existing root/package/app/tool/example/distribution/native owner path mapping exactly; it selects no catalogue, executable, quality policy or queue. Tool imports remain compatibility exports. Consumer source capture must still validate file bytes, aliases and scope; a path listing is not source admission or authority. Body reader (2026-10-07, position-and-projection §5, item 23 and constraint IM-43): `src/locator.ts` reads the body behind a locator for `ia read`; the package root exports `parseLocator`, `readBody`, `SOURCE_LOCATORS` and `READ_CODES` with the `Locator`, `ReadBody`, `ReadBodyOptions`, `ReadCode`, `ReadRefusal` and `ReadResult` types, and the `./internal/locator` subpath also carries `fragmentText`, `markdownSection` and `headingAnchor`. `parseLocator(text)` returns the locator a text spells, or undefined: `<identity>` (a canonical `system/kind/facet/name` identity), `<identity>#<phase>/<Primitive>` (a cell address of the closed phases and primitives), `<identity>#<REQ-ID>` (a requirement id), or `<path>:<line>` (the last colon splitting the path from a positive safe-integer line). `readBody(handle, locator, {read, mounts?, includeRuntime?, within?})` reads in the handle's root view, or in the scope `within` names (R12 version 2 refinement), and returns `{ok: true, body: {locator, identity, kind, path?, digest, body, certified: false}}` or one `{ok: false, code, message, identity?, path?, line?, file?}` refusal; a locator that spells no form throws IA-RUNTIME-REQUEST-INVALID. A line locator reads the innermost admitted record whose source span holds the line. A cell or requirement locator reads the record, never its document: `fragmentText`, the text of the record's cells at that address in source order, or of its requirement with that id; `resolveMention` checks a request mention's fragment with the same function, so its refusal is unchanged. Otherwise a record whose word carries a source locator (`SOURCE_LOCATORS`: `work.source` for `@plan`, `@spec`, `@milestone`, `@task` and `@decision`, `reference.document` for `@authoring-guide`, `template.resource` for `@template`, each a text field its schema declares) and states it unconditionally reads the document it names, kind `document`, and any other record reads its own body (`bodyOf` in `src/render.ts`), kind `record`: the part of what recordText renders that the record states rather than structures, its `meaning.says`, a `@system`'s head `describes`, and nothing for a `@schema`. All five work schemas declare `work.source`, and each word reads it as a locator (decision work-source-locator, 2026-10-08, widening row 2d from `@plan` and `@spec`), since a plan's records name their sections of its document with it. A document path is canonicalized and must stay inside the record's tree, db `sourceTree` (D02a): the workspace root for the workspace's own `.ia/src`, and a package's or an installed store's directory as it is. An adopted mount's sources carry the `.ia/adopted/<id>/<revision>` label of a directory that does not exist, so its documents are read from the directory `mounts` binds that label to, which a host builds from db `adoptedBindings`; a record of an adopted mount `mounts` does not bind has an unreachable document. A document is outside an adopted mount's revision pin, which covers only the mount's `.ia/src` sources. The host supplies `read(path)`, which returns one workspace file's bytes at its canonical workspace-relative path and throws for a path it does not admit, as R10's hosts hold the root boundary; runtime itself reads no file. The bytes must be UTF-8. A `#<anchor>` on the locator of a `.md` or `.markdown` file, in any case, selects `markdownSection`: from the ATX heading whose `headingAnchor` equals it, to the next heading of the same or a higher level, a repeated anchor numbered `-1`, `-2` in document order. `headingAnchor` slugs a plain-text heading as GitHub's slugger does: an inline link keeps its text, letters are lowercased, characters other than letters, marks, decimal and letter numbers, connector punctuation, `-` and space are dropped, and spaces become `-`. The heading is not rendered first, so underscore emphasis, entity and character references, inline HTML and reference links keep their markup, and such a heading may have another anchor on GitHub. A leading byte order mark is not part of the first heading and stays in the section. Headings in fenced code are ignored, and setext headings and headings in list items or block quotes are not read. `digest` is the SHA-256 of the body's UTF-8 bytes, so a whole document's digest is its file's. A read never certifies its body. The refusal codes, registered in RUNTIME_CODES as `READ_CODES` and covered by compliance boundary fixtures: IA-RUNTIME-READ-UNADMITTED when no admitted record answers the locator, which for an identity a source holds whose record admission refused reads `in this workspace's sources, but admission refused it` with that record's path and line and `file` `refused`, for any other identity is `not in this workspace's sources`, and for a line names what the workspace's sources hold in its file (`file` `refused` when admission refused records there, else `admitted` when admitted records there span other lines, absent when no record of the sources is in it, and a path that is absolute or escapes the workspace reads as one that is not relative to the workspace root); IA-RUNTIME-READ-PLACEMENT for a record at runtime placement (band 0) unless `includeRuntime` is set, judged before any fragment; IA-RUNTIME-READ-FRAGMENT when the record has no cell or requirement at the fragment; and IA-RUNTIME-READ-UNREACHABLE when the document path names no file, is a URL (a read fetches nothing, and a URL is never canonicalized into a path) or is outside the workspace or the record's tree, the record is in an adopted mount `mounts` does not bind, the host's reader throws, the bytes are not UTF-8, an anchor names a file that is not markdown, or no heading has the anchor. The Door's `read` operation (R12 version 2 refinement) reads a body through a scope.

Delivery view (2026-10-08, position-and-projection §9 step 2, §10 and rows 20 to 22; plan amendments A5 to A7): `src/next.ts`, exported from the package root and the `./internal/next` subpath, publishes `deliveryView(handle, within, seat?)` and `NEXT_CODES` with the `CycleRow`, `DeliveryMilestone`, `DeliveryResult`, `DeliveryTask`, `DeliveryView`, `ExitEvidence`, `NextCode`, `NextRefusal`, `Prerequisite`, `ReviewItem`, `StateDimension` and `StateLine` types. It is a pure function of the admitted records the scope token `within` reads: every read (the snapshot, directed views, one traversal, readiness) carries that token, so a narrowed scope lists only what it admits and prunes rows to it (db D09), and only a whole-workspace token (db `isCompleteScope`, PT5) also reads the admission findings it alone may disclose, `refused` and the report's COMP-PARSE findings; the view is computed per call, never stored, and nothing is written, the capture pair that `readiness` reads included; an unknown, stale or closed token keeps its database error. It returns `{ok: true, view}` or one refusal `{ok: false, code, message, next, plans?, cycle?}` whose `next` is exactly one command (design row 27), as `readBody` returns its refusals as values. The plan is the seat's when a seat is given: a `@plan`, the plan a `@milestone`'s `work.plan` names, or that of a `@task`'s `work.milestone`; without one, the only admitted `@plan` at band 100. IA-RUNTIME-NEXT-SEAT refuses a seat the scope does not admit (next `ia next`) or that is not a `@plan`, `@milestone` or `@task` (next `ia position --seat <seat>`); IA-RUNTIME-NEXT-NO-PLAN a seat that belongs to no admitted plan, or no seat and no plan at band 100 (next `ia next --help`); IA-RUNTIME-NEXT-AMBIGUOUS no seat and several plans at band 100, listed in the message and in `plans` (next `ia next --seat <the first of them>`); IA-RUNTIME-NEXT-CYCLE `require` rows that form a cycle among the plan's tasks, milestones or both, listed in `cycle` as declared rows `{from, to, declaredOn, path, line}`, each `from` requiring its `to` (next `ia position --seat <the cycle's first task, else its first milestone> --shape sequence`). Design §11 names `ia preview plan` and `ia preview --set` for the second and fourth; those verbs arrive later, so each refusal names a command of this milestone. The plan's milestones are the `@milestone` records whose `work.plan` names it, and its tasks the `@task` records whose `work.milestone` names one of them (the reverse field index). Order: one topological sort, Kahn's algorithm, over the tasks and two vertices per milestone, its start (its prerequisites met) and its end (satisfied). A milestone's tasks follow its start and precede its end, its start precedes its end, and each declared `require` row between two records of the plan, in either spelling, makes the requiring record (a task, or a milestone's start) follow the required one (a task, or a milestone's end). Ready milestone vertices are emitted first and ready tasks by (milestone identity, task identity), so tasks come prerequisites first with ties by milestone then task: the order Kahn's algorithm gives over the task-level expansion (a task follows each task it requires, each task of a milestone it requires, and each prerequisite task of its milestone, required directly or through a required milestone's tasks), and a required milestone with no task still passes on its own prerequisites, so a cycle through it is refused too. Requirements outside the plan order nothing and remain basis lines. A task's effective prerequisites are its own `require` targets, then its milestone's, each target once, an inherited one marked `via` that milestone. work-system consents `require` to a `@task`, `@milestone` or `@decision` target only (a `@task` that requires a `@spec` is refused at admission, IA-GRAPH-EDGE-UNCONSENTED), so no required-spec line arises; a requirement no admitted record answers, an admission warning with no row, is read from the traversal's dangling rows and is never satisfied; and a `require` the task or its milestone itself declares that gives neither a row nor a dangling edge in the scope, as when its answer is outside it (D09 prunes the row, and the traversal never crosses the scope), is never satisfied either, its state unknown. A requirement declared only on a record outside the scope is not read. A record's exit evidence is the first `@observation`, by identity, that its `work.exit-evidence` names or whose `evidence.subject` names it, whose `evidence.verdict` is success and whose `evidence.subject-revision` reads `current` under `readiness` (db D08) for that record; its evaluator is `evidence.evaluator`, and its `attribution` is `self` when that equals the identity the task's `work.owner-agent` names (decision task-owner-and-agent-description), `unknown` when the task states an owner-agent that no admitted `@agent` in the scope answers or the observation records no evaluator for a task that names one, else `other`. Basis lines: `decision <d>: choice made` or `no choice` (`decision.choice` stated or not); `task <t>: exit evidence <o>` or `no exit evidence`; `milestone <m>: exit evidence <o>` (its own), `every task has exit evidence`, `exit evidence missing for <n> of <k> tasks`, `no task and no exit evidence`, or `every task the view reads has exit evidence; records outside this scope are unknown` (a narrowed scope) or `…; records admission refused are unknown` (a whole-workspace scope while admission refuses a `@task`, whose `work.milestone` the view cannot read, or a file a language error refuses whole, db D03), neither of which satisfies it; `<reference>: no admitted record answers it`; `<reference>: no record in this scope answers it (unknown)`; each with ` (via <milestone>)` when inherited. The verdict `line` is `exit evidence recorded (<o>, evaluator <e>[, self-attributed | , self-attribution unknown])`, else `no declared blocker` when every effective prerequisite is satisfied, else `blocked (<each unsatisfied basis>; …)`; a record's `work.status` is printed as `status <value> (self-declared)` and is never a basis. The five state lines of each task (design §10): intent `superseded` when a record that supersedes the task is grounded by a live `@decision` stating `decision.choice` and `decision.effective-revision`, `accepted` when the task itself is, else `unknown`, naming the first live grounding decision's missing choice or effective revision, or that none grounds it (in this scope, on a narrowed one), the live decisions grounding a record being those no other of them supersedes, unless the two supersede each other through a cycle, which removes neither (revisions are compared by equality only, never ordered); definition `admitted` at the record's per-record digest, as every listed task is an admitted winner, so the plan's `rejected` cannot arise on a listed task: a `@task` admission refused has no record to list, and a whole-workspace view names it as an `admission` review item instead; realizable and realized `not applicable` (a task binds nothing and no effect owner realizes one); worked `observed success` or `observed refusal` for an observation at the current digest, `stale` for one whose subject-revision is the previous snapshot's digest, `unknown` for one at neither (or with no subject-revision, or another verdict), and `unobserved` when no observation names the task, `unknown` on a narrowed scope. Review items, each naming as owner the `head.steward` of the `@system` of the record it is about when the scope admits that system: `grounding`, two or more live `@decision` records grounding the plan or one of its milestones or tasks, the message naming those that supersede one another in a cycle; `currency`, two `@spec` records whose `work.status` is accepted, one superseding the other with no `work.replaced-scope` (a partial supersession keeps both live, and a draft or superseded spec is not current); and, on a whole-workspace scope only, `admission`, each `@plan`, `@milestone` or `@task` record admission refused that no admitted occurrence answers, with its path, line and reason, and each file a COMP-PARSE error refuses whole, without an owner, both naming `ia validate`. `next` is `ia position --seat <task> --shape sequence` for the first task in order whose verdict is `no declared blocker`, so tasks with exit evidence are skipped; it is null when every task has exit evidence or every other task is blocked, and `summary` says which, its every-task line reading `every task the view reads has exit evidence (<n> of <n>); <why>` while a task may go unread as above or admission refuses a `@milestone`, whose tasks the view then cannot list.
