# @inventarch/runtime

Coordinate-based procedure and governance delivery over scoped database reads. [SPEC.md](SPEC.md) owns the behavior and runtime/hosts plan owns delivery.

The initial classifier and coordinate preparation API validate the native axes, retain declared/profile/derived/absent provenance, and keep shape focus lists separate from scalar selector constraints. Hosts must explicitly declare phase and primitive. A scope key is the other way in: `normalizeScopeKey(partial)` completes K = (seat, shape, phase, depth 0..2, budget 0..64, word) with the design's defaults (a partial naming nothing is `K0`; otherwise context, the anchor phase of the shape's primitive, depth 1 and budget 16), and `resolveScopeKey(handle, within, key)` validates it against the scoped read, resolves its seat to `{kind, identity?, path?, unknown?}` (`workspace` when none is named, the `@workspace` the database seats the repository root at; `record` for an identity; `location` for a path, workspace-relative or absolute inside the root, read by `rootRelative(root, path)`, the absolute-path rule `ia read` shares, whose database resolution, with the record it is declared at and its claimants, is returned beside the seat) and derives its primitive from the shape row, so shape and phase complete it; `K0` and `SCOPE_KEY_CAPS` are exported beside them (SPEC R14). `positionBody` (below) assembles the body a resolved key gives, and the version 1 `context`/`select` requests still need a declared primitive. Use `context(handle, {within, text, coordinate}, {tokens, records})` for scoped cell/governance/selector/subject/text delivery. It returns a packet or an explicit refusal, reserves blocking governance before optional entries, and reports text-estimator usage and separate envelope overhead. `select` applies the same ranking to explicit candidates and refuses ties or missing selector axes. `Door` exposes validated JSON read operations over a private scope issuer; privileged reports require host opt-in. CLI/MCP transports now expose that door. evaluateSteward resolves a system's typed native owner and evaluates an explicitly trusted actor; the steward-hook app owns host identity/path interpretation. Model execution and capability dispatch have separate owners. `@inventarch/runtime/entry` exports `isEntry`, which the `ia`, `ia-mcp-door` and `ia-mcp-service` binaries use to run when a link such as npm's `.bin` entry reaches them. `readBody(handle, locator, {read, mounts})` returns the body behind a locator (an identity, a cell or requirement fragment, or a source path and line) with its SHA-256 and never a certification: a fragment's own text, that of the record's cells at the address or of its requirement; else the document a record's source locator names, or the section under its markdown anchor, read through the host's `read` (an adopted mount's document from the directory `mounts` binds its tree label to); else the record's own `meaning.says`. `ia read` is its consumer.

`positionBody(handle, within, resolved)` (also on `@inventarch/runtime/internal/position`) returns body(K), `ia.position-body.v1`, for a key `resolveScopeKey` resolved through the same scope token, and writes nothing: the seat; the composition one level from it at cost 0 (its field references both ways, a workspace seat's capture members, a `@system` seat's word members, a location's declared-at record and claimants); the seeds the shape's kind or lane focus picks from it; the records reached by up to `depth` hops along the shape's predicate focus in either direction, never inside another workspace's declared root, a row that carries a condition followed only where it holds at the key's coordinate, as graph traversal follows it; the blocking governance among those candidates, reserved in `rules` outside the budget; `loaded`, the seat and the first `budget` of the rest in the design's total order; the pointers (the 9-tuple id, word, kind, lane, owner system, steward, band, hop and reaching row or field), 48 listed and the rest tallied per word and owner system; the frontier one hop past `loaded`, tallied per owner system and kind; the unknowns, such as a workspace that declares no sources; the counts; and the two widening keys. The `@law`, `@convention`, `@principle` and `@playbook` records whose `subject.subject-word` or `subject.subject-kind` names the word or kind of a loaded record, or of a blocking candidate reserved in `rules`, are listed in `appliesByWord` as a field match, not a row, each once with its re-seat key (48 listed, the rest tallied); the first four such playbooks give `cells`, each its cell at the key's phase and the shape's primitive as `ia read` reads that address, or the nearest phase with one; a blocking rule that applies by word to any candidate, whatever the budget truncates, is reserved in `rules`; and `mandates` lists the `@mandate` records that claim a location seat or whose `authority.scope` names the seat's workspace (SPEC R17). With a `word`, only records of that word load (the seat loads whatever its word), are pointers or are tallied, and a record of another word a hop reaches is only a waypoint; the word never filters `rules`, `appliesByWord`, `cells` or `mandates`, so it hides no blocking rule that governs what loads. It is a pure function of the key and the admitted records the token reads, and only a whole-workspace token also reads the admission findings it alone may disclose (a narrowed one names that it reads none), with no root path, token, time, capture state or record body in it, only the playbook cells it delivers (SPEC R15). A record at runtime placement (band 0) is no part of it: never composition, a seed, a hop, loaded, a rule, a pointer, a tally or frontier, nor a location's declarer or claimant, and a seat at runtime placement is refused.

`position(handle, within, partial?)` (on the package root and the same subpath) is the call a host makes: it completes the partial key with `normalizeScopeKey`, resolves it, assembles the body and returns `{body, digest, hostNote}`, `digest` being graph's codec digest of the body and `hostNote` the undigested host state `{revision, capturedRevision?, previousRevision?, freshness, key}`, where freshness is `current`, `stale` or `no-capture` against the capture `ia capture` last wrote and `key` is the key used. Request text and tokens are refused as key parts, so nothing text-driven runs; two roots give one body and digest, and writing a capture moves only the note. The body's revision still hashes runtime-band sources, so one appearing moves that revision and the digest. Admission's findings and the database's seat and root decisions still read every placement too, so a runtime-band record that an authored loaded record's reference names also takes that reference's missing-target or missing-field-reference finding out of the body's unknowns (SPEC R15, R16). Installed state is not reported yet. The `Door`'s `position` operation serves a position (below), and `ia position` prints one.

`deliveryView(handle, within, seat?)` (also on `@inventarch/runtime/internal/next`) reads one plan's delivery view through a scope token and writes nothing: its tasks in one prerequisites-first order (ties by milestone, then task), each with the basis lines of its own and its milestone's requirements, a verdict (`exit evidence recorded (…)`, `no declared blocker` or `blocked (…)`) and the five state lines, plus review items and `next`, the `ia position` command for the first task with no declared blocker. What the scope does not read never counts as met: a requirement whose answer lies outside it blocks as unknown, and no milestone is satisfied through its tasks while one may go unread (a narrowed scope, or a refused `@task` or file, which a whole-workspace scope lists as review items). A relation row that carries a condition counts only where it holds at the coordinate the scope binds, as graph traversal decides it: the record that states it decides a provenance or artifact-set term, and a severity term where its own severity decides it at every coordinate; a term on an axis the scope binds no value for (the phase on the whole-workspace scope `ia next` reads, the severity on every scope) leaves it conditional with an unknown basis, never met, and an intent such a row could change is unknown, while one it cannot change at any coordinate reads as it does everywhere. A seat that is no plan, milestone or task, a missing or ambiguous plan and a require cycle are refusals (`NEXT_CODES`), each naming one next command. The `Door`'s `next` operation serves it.

The `Door`'s `read` operation, which `MACHINE_PROTOCOL` version 2 appends with `since: 2` and the MCP tool `ia_read`, serves `readBody` through the door's scope token: `ReadBodyOptions.within` binds every lookup to that scope, and in a scope narrower than the whole workspace a locator no admitted record in it answers is one plain `IA-RUNTIME-READ-UNADMITTED` that names nothing beyond it. A whole-workspace token, one whose scope is at the workspace root with no `phase` or `identities` and was issued under no narrower one (db `isCompleteScope`), such as the initial one of a door opened without a `boundary` or one `scope` issues from it without narrowing it, reads what the root view reads, so its refusal says what the workspace's sources hold, a record admission refused named with its path, line and `reason`, as `next` names one. The door's reader names a document by its workspace-relative path, never by where the server keeps the workspace. The door reads documents through `DoorOptions.read`, by default db `readWorkspaceBytes`, which admits the paths the CLI's workspace file reader admits, within the same 4 MiB, and binds adopted mounts once, when it opens, from the `.ia/workspace.json` bindings, as `ia read` does; so `ia read` returns the Door's body and digest, and refuses a document the Door refuses with the same code. The nine version 1 rows are byte-identical to 1.1.0's. `DoorOptions.protocol` is the protocol version a door serves, by default the table's: a door at version 1 refuses `read` as the unknown operation 1.1.0 refused, and the CLI's machine routes open theirs at version 1, so they stay those nine; on the CLI `ia read` reads a body.

The `Door`'s `next` operation, which `MACHINE_PROTOCOL` version 2 appends with `since: 2` and the MCP tool `ia_next`, takes `{within?, seat?}` and answers with the view `deliveryView` returns through the door's scope token, or with its refusal as that function returns it: a version 2 operation's refusal may carry more than 1.1.0's `{ok, code, message}`, here `next`, the one command to run, and the `plans` or `cycle` it names, while a version 1 operation's refusal, and every refusal the Door raises itself, keep that shape. A door serving version 1 refuses `next` as an unknown operation, so the CLI's machine routes do not serve it; on the CLI `ia next` prints the view.

The `Door`'s `position` operation, which `MACHINE_PROTOCOL` version 2 appends with `since: 2` and the MCP tool `ia_position`, takes `{within?, seat?, shape?, phase?, depth?, budget?, word?}` and answers with `{body, digest, hostNote}`, exactly what `position` returns for that partial key through the door's scope token: no params is K0, and the parts take `normalizeScopeKey`'s defaults, so one key gives one body and digest wherever the workspace is. The params are closed, so request text is refused and nothing text-driven runs. A refusal of the key carries `next`, the one command to run, which the `RuntimeError` that `position` throws also carries: the closed set of a shape or phase, the cap of a depth or budget, `ia vocabulary` for a word, or the position without a seat the scope does not hold or one at runtime placement (the overview, when that seat is the repository's own `@workspace`). The Door's own refusals keep 1.1.0's shape, and a door serving version 1 refuses `position` as an unknown operation; on the CLI `ia position` prints a position.
# Editor and authoring consumers

`@inventarch/runtime/editor` exposes `EditorWorkspace`: cache-free local source capture, versioned overlays, diagnostics, completion, source actions, inspector/graph projection, schema-backed drafting and create-only candidate validation. `ViewStamp` binds opaque source actions to one root owner and generation; refresh/update invalidates prior actions. This is a privileged local facade, not a replacement for scoped remote Door APIs. It performs no file creation or network requests.

`@inventarch/runtime/authoring` owns protocol-1 disclosure/request/proposal/receipt/event validation, digests and bounded same-origin HTTPS transport for separately configured account services. Applications own auth tokens, service state, model calls and effects. The extension and separate API use these same contracts; no native brief/spec/plan vocabulary is introduced.

See Workbench evidence and the [VS Code guide](../../apps/vscode/README.md) for actual consumers and qualification limits.
