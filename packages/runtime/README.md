# @inventarch/runtime

Coordinate-based procedure and governance delivery over scoped database reads. [SPEC.md](SPEC.md) owns the behavior and runtime/hosts plan owns delivery.

The initial classifier and coordinate preparation API validate the native axes, retain declared/profile/derived/absent provenance, and keep shape focus lists separate from scalar selector constraints. Hosts must explicitly declare phase and primitive. Use `context(handle, {within, text, coordinate}, {tokens, records})` for scoped cell/governance/selector/subject/text delivery. It returns a packet or an explicit refusal, reserves blocking governance before optional entries, and reports text-estimator usage and separate envelope overhead. `select` applies the same ranking to explicit candidates and refuses ties or missing selector axes. `Door` exposes validated JSON read operations over a private scope issuer; privileged reports require host opt-in. CLI/MCP transports now expose that door. evaluateSteward resolves a system's typed native owner and evaluates an explicitly trusted actor; the steward-hook app owns host identity/path interpretation. Model execution and capability dispatch have separate owners. `@inventarch/runtime/entry` exports `isEntry`, which the `ia`, `ia-mcp-door` and `ia-mcp-service` binaries use to run when a link such as npm's `.bin` entry reaches them.
# Editor and authoring consumers

`@inventarch/runtime/editor` exposes `EditorWorkspace`: cache-free local source capture, versioned overlays, diagnostics, completion, source actions, inspector/graph projection, schema-backed drafting and create-only candidate validation. `ViewStamp` binds opaque source actions to one root owner and generation; refresh/update invalidates prior actions. This is a privileged local facade, not a replacement for scoped remote Door APIs. It performs no file creation or network requests.

`@inventarch/runtime/authoring` owns protocol-1 disclosure/request/proposal/receipt/event validation, digests and bounded same-origin HTTPS transport for separately configured account services. Applications own auth tokens, service state, model calls and effects. The extension and separate API use these same contracts; no native brief/spec/plan vocabulary is introduced.

See Workbench evidence and the [VS Code guide](../../apps/vscode/README.md) for actual consumers and qualification limits.
