# @inventarch/runtime

Coordinate-based procedure and governance delivery over scoped database reads. [SPEC.md](SPEC.md) owns the behavior and runtime/hosts plan owns delivery.

The initial classifier and coordinate preparation API validate the native axes, retain declared/profile/derived/absent provenance, and keep shape focus lists separate from scalar selector constraints. Hosts must explicitly declare phase and primitive. A scope key is the other way in: `normalizeScopeKey(partial)` completes K = (seat, shape, phase, depth 0..2, budget 0..64, word) with the design's defaults (a partial naming nothing is `K0`; otherwise context, the anchor phase of the shape's primitive, depth 1 and budget 16), and `resolveScopeKey(handle, within, key)` validates it against the scoped read, resolves its seat to `{kind, identity?, path?, unknown?}` (`workspace` when none is named, the `@workspace` the database seats the repository root at; `record` for an identity; `location` for a path, workspace-relative or absolute inside the root, whose database resolution, with the record it is declared at and its claimants, is returned beside the seat) and derives its primitive from the shape row, so shape and phase complete it; `K0` and `SCOPE_KEY_CAPS` are exported beside them (SPEC R14). Nothing assembles a body for a key yet, and the version 1 `context`/`select` requests still need a declared primitive. Use `context(handle, {within, text, coordinate}, {tokens, records})` for scoped cell/governance/selector/subject/text delivery. It returns a packet or an explicit refusal, reserves blocking governance before optional entries, and reports text-estimator usage and separate envelope overhead. `select` applies the same ranking to explicit candidates and refuses ties or missing selector axes. `Door` exposes validated JSON read operations over a private scope issuer; privileged reports require host opt-in. CLI/MCP transports now expose that door. evaluateSteward resolves a system's typed native owner and evaluates an explicitly trusted actor; the steward-hook app owns host identity/path interpretation. Model execution and capability dispatch have separate owners. `@inventarch/runtime/entry` exports `isEntry`, which the `ia`, `ia-mcp-door` and `ia-mcp-service` binaries use to run when a link such as npm's `.bin` entry reaches them. `readBody(handle, locator, {read, mounts})` returns the body behind a locator (an identity, a cell or requirement fragment, or a source path and line) with its SHA-256 and never a certification: a fragment's own text, that of the record's cells at the address or of its requirement; else the document a record's source locator names, or the section under its markdown anchor, read through the host's `read` (an adopted mount's document from the directory `mounts` binds its tree label to); else the record's own `meaning.says`. `ia read` is its consumer.
# Editor and authoring consumers

`@inventarch/runtime/editor` exposes `EditorWorkspace`: cache-free local source capture, versioned overlays, diagnostics, completion, source actions, inspector/graph projection, schema-backed drafting and create-only candidate validation. `ViewStamp` binds opaque source actions to one root owner and generation; refresh/update invalidates prior actions. This is a privileged local facade, not a replacement for scoped remote Door APIs. It performs no file creation or network requests.

`@inventarch/runtime/authoring` owns protocol-1 disclosure/request/proposal/receipt/event validation, digests and bounded same-origin HTTPS transport for separately configured account services. Applications own auth tokens, service state, model calls and effects. The extension and separate API use these same contracts; no native brief/spec/plan vocabulary is introduced.

See Workbench evidence and the [VS Code guide](../../apps/vscode/README.md) for actual consumers and qualification limits.
