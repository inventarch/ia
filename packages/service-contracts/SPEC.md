# Public interoperability contracts

Marketplace release terms admit 1–16,384 characters so the complete Apache-2.0 text can be retained; the codec refuses empty/oversized terms. Consumers pinned to the earlier 8,192-character bound require a refreshed artifact. Existing transport bounds remain in force.

`@ia/service-contracts` owns browser-safe structural service wire contracts under the Apache-2.0 license. Zod is its only runtime dependency. Importing any export initializes no filesystem, network, identity, native runtime, provider or storage. Installed consumers use emitted JavaScript and declarations; development source conditions are removed during packing.

| Export | Contract owner |
|---|---|
| `.` | Version/limits, binding, offering/operation descriptors, invocation, public sessions/events, errors, strict decoding and JSON Schema |
| `./tenancy` | Organization, department, membership and workspace commands/views/pages |
| `./sources` | Exact source references, upload/history/admission and bounded file chunks |
| `./session-lifecycle` | Directory summaries, continuation and deadline renewal intent |
| `./source-apply` | Exact candidates, preparation, review, application and bounded inspection |
| `./marketplace` | Native release descriptors, publication selectors, acquisition quotes/receipts and bounded artifact chunks |
| `./installation` | Installation planning, explicit review, application and inspection |

Objects reject unknown fields. Selectors, permissions in a published view, command IDs, digests and opaque tokens are data, never grants. Exact source byte verification, semantic admission, current tenancy authorization, disclosure filtering, replay, scheduler fencing and effects belong to an independently supplied host. No SQL directory, marketplace implementation, transport, private word implementation or inspection method is included. Internal compatibility exports expose the same pure modules; they do not expand authority.

The original strict codec tests remain public obligations rather than being renamed or removed. Release qualification must preserve their expanded case identities, inspect archive dependencies/exports and exercise an independently packed/installed consumer. That consumer validates tenancy success/refusal, operation invocation and installation reads, imports every subpath with ordinary and development Node conditions, and bundles with a browser target. This proves an interoperable emitted boundary, not hosted authentication, deployment, registry publication or a complete application journey.
