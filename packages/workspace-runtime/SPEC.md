# Workspace runtime specification

Captured `structured-v1` templates render their selected JSON resource. Legacy `parameters` and `lines` may be omitted or present as empty lists; nonempty, repeated or conditional legacy fields are refused. Scalar rendering still requires both fields through its own renderer contract. Resource disclosure, current scope and output validation remain mandatory in either form.

## Boundary

`@inventarch/workspace-runtime` is the generic workspace runtime. It owns workspace capture and adoption, captured resources, projections, publication and candidates, templates, lifecycle, authoring index and manifest, installed catalog and source policy, sources, the local store and adapters, and the host files and definitions generated from authored records (W01 to W04), the host plugin rendered from a product `@distribution` (W05) and the lowering of a host plugin into records (W06). The composition compiler (catalog, compile, compiled, execution, fields, inputs, installed read, task capture, task context declaration, task teaching closure, draft tools) stays in `@inventarch/agent-composition-system`, which depends on this package. There is no reverse edge: no module here imports `@inventarch/agent-composition-system`, and `tests/boundary.test.ts` fails if one appears.

`installedImplementationDigest` pins the installed bytes of this package and its fixed first-party dependencies. An upper package pins its own installed entrypoint by passing it as an additional entry; the entries are never record- or model-supplied paths. Each pinned package directory is walked within the steward hook implementation bounds (depth 16, 2,000 entries, 8 MiB per code file and 32 MiB per package); a larger tree or a nonregular code file is refused with `IA-CORPUS-DENIED`, never truncated, and `tests/installed-catalog.test.ts` exercises each bound. Each code file is opened once and read through the descriptor whose size was bounded; a file that grows while it is read, or an entry swapped for a link, socket or device after its directory was read, is refused with the same code.

## Host generation

W01. Agent files from authored agent profiles (2026-10-09, revised 2026-10-11; runtime R19 and R20): `src/generate/agent-profile.ts`, exported through `src/generate/index.ts` on the `./internal/generate` subpath only, publishes `generateAgentProfiles(reader, within, host)`, which returns a frozen `GeneratedSet`, `{files, unsupported}`: `files` the `GeneratedFile` rows `{path, text, identity, word: 'agent-profile'}`, `unsupported` the `UnsupportedRecord` rows `{identity, word, reason}` the projection receipt's `unsupported` section holds. Only `@agent-profile` records at band 100 that the scope token `within` admits are read, by identity; a profile below band 100, where an installed or adopted base places its records, renders nothing and is not reported, and no system steward renders, a steward being an `@agent`. For `codex` every authored profile is an unsupported row: a codex agent needs an entry in `.codex/config.toml`, which holds the owned MCP block. For `claude` each profile renders `.claude/agents/<profile name>.md`, unless it is reported instead: its name is no portable host name (`safeName`: lower-case letters, digits and single hyphens, a letter first and no hyphen last, at most 64 characters, no Windows device name, `com0` and `lpt0` included); its capabilities allow no host tool (claude gives an agent with no tool list every tool, so only an unwritten file grants nothing); the composition compiler would refuse its capability closure (`closureRefusal`: an inclusion cycle, or an included capability with an effect its includer does not declare, the compiler holding each capability's own `execution.effects` as the ceiling of what it includes); or its text is not inert prose (projection-host's `inert`: no executable dynamic context, no active HTML, no unbalanced code span or fence), judged on each authored value before rendering, so the reason names what the record itself holds, and on the rendered file. One record's refusal never fails the others. Any other host is IA-PROJECTION-INPUT-INVALID, and for either host an unknown or stale token keeps its database code. A profile's capability closure is its `composition.capabilities` and every capability they include through `composition.includes`, each once (`capabilityClosure`). The file is YAML frontmatter: `name` the JSON-quoted profile name; `description` the JSON-quoted `meaning.says` of its `composition.agent` when the workspace authors that `@agent`, else the profile's own, so an installed or adopted base's text never decides when claude delegates; and `tools`, the claude names of the host tools the `execution.effects` of the profile's own `composition.capabilities` cover (each bounds what it includes, so the closure adds none) through `PROSE_EFFECT_TOOLS` (`read` covers Read, Grep and Glob; no other effect maps a tool), first-stated and each once, as one JSON-quoted comma-separated string. Then a blank line and runtime's `PACKET_MARKER` on its own line, and a body read only from the records the profile's own fields reference, each resolved through the same token: the title, the profile's `meaning.says`, its identity and its agent's; `## Mandate`; `## Voice`, when `composition.voice` is set, its identity and each `communication.*` field; `## Tools`, one line per capability of the closure naming its operations, effects and host tools, after a line for each `composition.capabilities` reference no admitted capability answers; and `## Delegates`, one line per `composition.delegates` reference, never refused. `## Mandate` holds the profile's own `composition.mandate` as one list item, its identity, with `authority.participant`, `moves`, `scope`, `excluded-words`, `covers` and each `execution.limit-*` it states nested beneath it, as authored and never judged. A profile that names none falls back to the runtime's mandate resolver: the authored mandates `governingMandates(reader, within, {actor})` returns for its `composition.agent` that bind it (`binds !== false`, so a mandate naming no participant is included, unless it states neither scope nor covers and so governs no path), each as such a group, after a line labelling them as the fallback and saying the guard refuses the agent where a mandate that binds another participant governs and none of these grants the move; the agent is the one a subagent acts as for the edit guard, so the file states what that guard enforces. Every rendered profile separately explains that CLI commands choose an authored workspace participant or steward and that omitting `--actor` uses the workspace's default actor, rather than selecting the profile's agent. When none binds the line says so; when the resolver cannot read a mandate (IA-RUNTIME-REQUEST-INVALID) or the agent is not an admitted `@agent`, the line says the fallback is unavailable and why. The fallback is resolved only for a rendered profile that needs it. When the profile's own mandate names a participant other than its agent, a nested line says so: the edit guard judges the agent by the mandates that bind it. Free text is written with runtime's packet helpers (`inline`, `code` and `prose` on `./internal/packet-host`): on one line, each bare IA word token a code span in the body; every C0 or C1 control but tab and the folded line breaks, the Unicode line and paragraph separators and the bidirectional controls become spaces; `<!--` is written `&lt;!--`, a `!` that a rendered code span would follow `&#33;`, and a leading `<` `&lt;`, so no authored value starts a YAML or Markdown line, equals a marker line, opens a comment that hides what follows, reads as dynamic context or opens an HTML block. A reference is printed as the identity it resolves to, or as authored with `not admitted in this scope` where its fields would be read; a field contributes only its unconditional values. The text is a function of the scope's records alone: no absolute path, time, scope token, revision or package version. Generation reuses the prose catalog, the effect table, `inert` and `nativeValue`, not `compileProjection`'s descriptor and publication machinery. Nothing here applies the files: they go to the CLI's `applyHostProjection`, which lists them in the receipt. `tests/generate-agent-profile.test.ts` lays apps/cli's composition fixture (`tests/fixtures/composition-workspace`) over the conformance corpus adopted at band 90 and pins: the fixture profile's exact file, its own mandate's other-participant line included, and an empty unsupported list, frozen; the fallback naming the mandates that bind the reviewer agent and not the demo participant's, a participant-less mandate included and one that locates nowhere left out, the line for none binding, and an unavailable fallback for an admitted empty move list and for an unadmitted agent, while a profile that names its mandate and a workspace with no profile never resolve it; a named mandate's nested bounds; delegates; unsupported rows for profiles allowed no host tool, for unportable names and for text that runs a command or holds active HTML, the others still rendered; IA words, controls, separators and comment openers in free text, and an adopted agent's text kept out of the description; one tools line per capability, the tools of a profile whose capability includes another, and a closure the compiler refuses (a cycle, an undeclared included effect) reported; a `!` before a rendered span and a leading `<?` escaped, and a lone backtick reported by the value's own reason; narrowed scopes; an adopted profile rendering and reporting nothing for either host; this repository's own `example-profile`; codex reporting every profile, an unknown host refused, a forged or stale token refused; and equal bytes at two roots and under a second token.

W02. Skills from authored playbooks (2026-10-09, revised 2026-10-11; runtime R19 and R20): `src/generate/playbook.ts`, on the same subpath, publishes `generatePlaybookSkills(reader, within, host)`, which returns a frozen `GeneratedSet` with `word: 'playbook'`. Only `@playbook` records at band 100 that the token admits are read, by identity: a playbook below band 100 renders nothing and stays the cells `ia position` delivers. For either host each renders one skill, `.claude/skills/<playbook name>/SKILL.md` for `claude` and `.agents/skills/<playbook name>/SKILL.md` for `codex`, with the same text, unless it is an unsupported row instead: its name is no portable host name (`safeName`), it is named `ia-authoring`, the one skill the packet renders for each host and the projection writer owns (a record's name is lowercase, so no spelling escapes this), or its text is not inert prose. The file is YAML frontmatter (`name` and `description`, the JSON-quoted name and `meaning.says`), a blank line and `PACKET_MARKER` on its own line, the title and identity, then one `## <phase>` section per phase in the cycle order orient, plan, act, learn (the language's `PHASES`), a phase with no cell left out: the primary primitive's cell first and marked `(primary)`, then the others in authored order, each with its condition's terms when it has one and its text written as W01 writes free text. The text is a function of the playbook's record alone. Nothing here applies the files. `tests/generate-playbook.test.ts` pins the fixture playbook's exact skill for both hosts, conditions and phase order, adopted playbooks rendering and reporting nothing, the reserved name reported for either host, unportable names and non-inert cells reported with the fixture's own skill still rendered, IA words and comment openers in cells, this repository's own `example-method`, refused hosts and tokens, and equal bytes at two roots.

W03. Hook declarations from authored hooks (2026-10-11): `src/generate/hook.ts`, on the same subpath, publishes `generateHookSet(reader, within, host)`, which returns a frozen `{hooks, unsupported}`, `generateHooks(reader, within, host)` (its `hooks`), `hookDeclaration(node)`, and `HOOK_IDENTITY`, `HOOK_IDENTITY_LIMIT` and `registrableHook(identity)`. Only `@hook` records at band 100 are read, by identity. `hookDeclaration` narrows one to what the `@mandate` edit guard decides, a frozen `HostHookDeclaration` `{identity, event: 'PreToolUse', tools, paths, message}`: `hook.event` PreToolUse, `hook.tools` one or more of Write, Edit and MultiEdit (deduplicated, canonical spelling), `hook.paths` one to 64 workspace-relative path selections in the G06c dialect written with `/` (`registrableSelection`: none empty, absolute, escaping, longer than 512 characters, holding a `.` or `..` segment or an empty one but the last, backslashed, or holding a C0, DEL or C1 control, a bidirectional control or a Unicode line or paragraph separator; `HOOK_SELECTION_LIMIT` and `HOOK_SELECTION_LENGTH`, the bounds distribution's hook registration holds its rows to), a message that is not blank, and an identity a registration can carry on the guard's command line (`registrableHook`: a canonical `system/kind/facet/name` of the language's lower-cased name characters, at most 512 characters). A hook's name is not a host path, so `safeName` does not apply. A hook that selects no path could never deny, so it is refused rather than registered as a guard that guards nothing. Anything else is IA-PROJECTION-INPUT-INVALID naming what is unsupported. `generateHookSet` registers each hook `hookDeclaration` accepts, up to `HOOK_LIMIT` (64), and reports each it refuses, and each accepted one past that bound, as an unsupported row with its reason, so one unsupported record never blocks the others; for `codex` it registers none and reports each (Codex hooks are unsupported). Tool values are never read as a regex or shell text, and nothing authored but the identity reaches a registered group: the tools and paths are validated, and the paths recorded in the registration's ownership state (distribution's guard-registration). The guard decides only the edits a hook's paths and tools select: a workspace protects its governing records, the `.ia/src` sources of its hooks, mandates and profiles, by selecting them, as `paths [".ia/src/**"]` does. Steward-hook's `--hook` mode reads the record through the same `hookDeclaration`, so the guard refuses what registration reports. `tests/generate-playbook.test.ts` pins the fixture hook, codex reporting it, an adopted hook neither registered nor reported, and other tools, an escaping selection, a C1 or bidirectional control in a selection, 65 selections, a 600-character selection, a 65th hook, another event, an empty path list and a blank message each reported, with `hookDeclaration` refusing the same record, and one unsupported hook leaving the others registered and the definitions rendering.

W04. Operation and harness definitions (2026-10-11): `src/generate/definitions.ts`, on the same subpath, publishes `generateDefinitions(reader, within, host)`, which returns frozen `PacketDefinition` rows (runtime's union of `{word: 'operation', definition: OperationDefinition}` and `{word: 'harness', definition: HarnessDefinition}`), the authored (band 100) `@operation` records first, then the `@harness` records, each by identity. An operation's definition is its name, `meaning.says`, `execution.handler`, `execution.input`, `execution.output` and `execution.effects`, a field it does not state absent; the handler and the two validator ids are catalog keys an installed implementation answers, copied as authored and never imported, resolved, served or executed here (the MCP door serves no new tool). A harness's definition is its name, `meaning.says`, `composition.workspace`, `execution.host-profile`, `composition.profiles`, `composition.bindings` and its registration set: the agent files rendered for its profiles, the skills rendered for the playbooks of their capability closure (W01; a closure the compiler refuses selects none), and the registered hooks its bindings' `binding.target` names, as identities and paths. A record the host does not render or register selects nothing, so hook or agent support never fails the definitions. `tests/generate-playbook.test.ts` pins both fixture rows exactly, the codex registration set, a harness whose profile reaches a playbook only through an include selecting exactly that skill and nothing of the fixture's, and nothing once the include closes a cycle, and this repository's `read-captured-source` row with handler `captured-source-read-v1` and its input and output validator ids.

W05. Host plugin from a product distribution (2026-10-14; the CLI's host plugins): `src/generate/plugin.ts`, on the `./internal/generate` subpath, publishes `renderPlugin(reader, within, resources, assets)`, which returns the frozen `PluginFile` rows `{path, bytes}` of one plugin directory, sorted by path, with no marker line. It reads the one authored (band 100) `@distribution` that states `product.name`; none or several is IA-PLUGIN-PRODUCT. One plugin carries every host the product's `product.hosts` lists: for each, the manifest `pluginManifest(product, host)` builds (`.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.grok-plugin/plugin.json`, two-space JSON with a final newline). A product that lists no host is IA-PLUGIN-PRODUCT, so no plugin is rendered without a manifest. Each authored `@capability` with an invocation mode `model` or `user` renders `skills/<name>/SKILL.md`: frontmatter (`name`, `description` from `meaning.says`, `disable-model-invocation: true` for `user`, `argument-hint`) through `emitFrontmatter`, then its one inline body resource byte for byte, then its installed references at their output paths. Each authored `@agent-profile` with an invocation mode renders `agents/<name>.md`: `name`, `description`, `tools` (the claude names of the effects of its capabilities, `Read, Grep, Glob` for `read`, through `toolsOf`), `model` from `execution.model-profile`, `color` from `presentation.color` and `effort` from `execution.effort`, then its inline body. A mode `none` renders nothing; `delegated` is IA-PROJECT-FEATURE ("not rendered by this version of ia"), as is a profile whose capabilities allow no host tool. Assets are copied at their output paths. An output path that is not relative, POSIX and free of empty, `.` and `..` segments, two sources for one path, a skill or profile without exactly one inline body, or a capability reference no admitted record answers is IA-PLUGIN-PRODUCT. `tests/generate-plugin.test.ts` pins the manifests and a user-invoked skill, a profile without an invocation rendering nothing, an agent file with its tools, references and assets, the duplicate and unportable paths, the Claude manifest's fields, a delegated capability, and a product with an empty or absent host list refused.

W06. Host plugin lowering and comparison (2026-10-14; the CLI's host plugins): `src/host-plugin/*`, on the `./internal/host-plugin` subpath only, which is not a stable contract. `errors.ts` holds `HostPluginError` and its codes. `frontmatter.ts` reads and writes the strict frontmatter subset (plain, double- and single-quoted strings, booleans and one-line lists of plain items; anything else, CRLF, a byte-order mark or non-UTF-8 bytes is unresolved, never normalized). `inventory.ts` reads a plugin directory (`readEntries`, `inventoryOf`, `readPlugin`): every regular file by sorted POSIX path, refusing a link, a `.git` or `node_modules` entry in any letter case, a non-regular file and more than 1,000 files or 16 MiB with IA-PLUGIN-INPUT, and classifying manifests, skills with their owned files, agents and other files; hooks, MCP and LSP configuration and `commands/` are unresolved. `manifest.ts` publishes `pluginManifest(product, host)`, the pure builder of the manifest object each host's `plugin.json` holds, which W05 writes and lowering compares against. `lower.ts` publishes `lowerPlugin(inventory, system)`, a frozen `LoweringPlan` of files, records, assets, the `ia.lowering-map.v1` map (every file and every accepted frontmatter key one disposition: field, resource, asset or derived; an agent's `name` derived as `@agent-profile <name>`, `model` to `execution.model-profile`, `effort` to `execution.effort`, `color` to `presentation.color`), `MIGRATION.md` generated from it, and the unresolved entries. Lowering admits only what W05 writes back: an agent's `tools` only as one string whose `split(', ')` rejoins to exactly the original; each manifest only when it equals, by `isDeepStrictEqual`, what `pluginManifest` builds for the lowered product, a Codex manifest's absent hook map excepted (each difference an unresolved entry naming the manifest and the key path); no explicit `disable-model-invocation: false`, which W05 omits (the reason says to remove the key). Its lowered system requires `agent-composition-system`, `agent-system`, `compliance-system`, `learning-system` and `workspace-system`, sorted, so trigger `@contract`, `@case` and `@observation` records can be authored in it. Every unresolved message says what "is not lowered by this version of ia", never a plan slice. `compare.ts` publishes `comparePlugin(original, rendered)` and `DIFF_RULES`: each file identical, ruled by named rules (`frontmatter-scalar-style`, `frontmatter-field-order`, `frontmatter-default-omitted`, `tool-order`, `manifest-format`, `codex-hooks-suppressed`), drift, missing or extra. `tests/host-plugin.test.ts` pins the frontmatter subset, the inventory and its refusals, lowering the sample byte for byte, each unresolved construct, the manifest builder against the sample, the tools forms and manifest variants lowering refuses or accepts, the agent dispositions, the wording and the comparison rules.

W02. Execution binding: `src/bind.ts` (`./bind`) joins each `@execution-binding` with the installed-implementation catalog's operation rows, typed by `@inventarch/db/distribution`'s `InstalledOperation`. `executionBindings(reader)` reads every admitted binding with its unconditional `binding.kind`, `binding.implementation` and `binding.target`, a stated target kept as the reference written and the identity it resolves to, null when no admitted record answers it (`BindingTarget`: a stated target is never read as no target); `bindExecution(binding, catalog)` returns `bound` only when the catalog is present, lists the implementation as available, the binding is an operation binding and its target, when it states one, resolves to the operation the implementation serves; `unavailable` when there is no catalog, it does not list the implementation, lists it unavailable, the kind has no catalog section, the stated target resolves to no admitted record (so the canonical `read-captured-source-binding`, copied into an `ia init` consumer that admits no `@operation read-captured-source`, is unavailable there) or the implementation serves another operation; `revoked`, an error, when the catalog revokes it or failed verification. The catalog is the one `@inventarch/distribution` read from the verified host payload; this package never imports the composition system, and nothing is loaded or executed.
