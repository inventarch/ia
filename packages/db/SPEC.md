# Database specification

Planned consumer: bounded repository capture specifies an explicit host collector over package-local sources. It must adapt supported public admission interfaces; it does not change this package's root discovery, adoption limits or create implicit parent/recursive scanning. Native revision and full code/toolchain identity remain distinct.

PT5 complete-disclosure refinement: `ReadHandle.isCompleteScope(token)` proves that a current handle-issued scope was created at the whole-workspace root without a phase or identity restriction, and has no narrowed ancestor. Unknown, stale and closed tokens retain existing scope errors. Selecting every admitted identity still returns false: refused source diagnostics may reveal material outside that identity set. The flag stays internal to scope storage, so serialized scope/snapshot shapes remain compatible. Whole-workspace draft preview consumers must require this proof before exposing admission diagnostics; ordinary scoped reads are unchanged.

## OS09 descriptor producer (LK-17)

The public `@inventarch/db/descriptors` entrypoint owns the pure, bounded, versioned codecs and compilers for `domain-model`, `storage-binding` and `app-composition` resources (spec-0009): strict 1 MiB/depth-16/1,000-entry JSON with duplicate-key refusal, canonical `sha256:` digests bound to the native envelope, a host-built trusted contract registry for command/query/validator/view/operation/port/adapter/migration-policy IDs, and typed single-diagnostic refusals with owner/source/resource/field attribution. It performs no I/O, DDL or code execution, and the three words remain unregistered (ALIGN-06); an isolated candidate is admitted only through `preview`. The strict JSON transport is shared with the distribution codec through `src/json.ts` with unchanged distribution messages. See the [descriptor SPEC](src/descriptors/SPEC.md).

## Distribution M1–M5 implementation packet

The public `@inventarch/db/distribution` entrypoint owns strict version-1 transport decoders and canonical bytes for release descriptors/manifests, portable locks, generation membership and activation pointers. JSON rejects duplicate decoded keys and unknown fields; object input must be bounded plain data without accessors or aliases. Native parsing stays in language. Package IDs are provider-qualified lowercase `provider/name`; versions and ranges use pinned SemVer. No absolute path or credential enters a portable lock. Metadata limits are 4 MiB, 128 selected bundles and 10,000 files, with the archive/file ceilings from DIST-05. Decoding copies and freezes output. A release descriptor's `distribution` is its one optional key (2026-10-09, milestone position-packet plan amendment B7): a workspace that releases nothing, as one a default `ia init` creates, omits it, and the decoded `ReleaseDescriptor` then has no `distribution` property; present, it must still be a native distribution identity, never null. A bundle manifest always carries one, and its decoded keys keep their order, so canonical bytes are unchanged.

Generation membership enumerates selected bundle IDs/archive digests and source inventories derived from verified manifests, with deterministic identical-system deduplication and contributing-package provenance. Readers verify complete file inventory, exact canonical generation bytes and the active lock, and load only selected source bytes. An unpinned regular file named `.DS_Store` or `._*`, which a Mac writes into directories it opens, is skipped; a pinned one is verified like any other, and a link or special file of such a name is refused (`platformDebris`, #323). Candidate installation is an explicit host-selected input option; it does not bypass admission or grant writes. The generated installation workspace uses native composition and direct-distribution use edges. Installed sources retain adopted band 90/methodology; generated installation state uses band 100/workspace. Active generation and monotonic counter participate in revision and scope freshness. Existing authored/adopted callers keep their behavior when no installation exists.

The application owns archive acquisition, bounded solving and mutation. The database owns no network or installation writes. Restore-required, lock-drift, corrupt-state and pending-recovery remain named operational refusals; a fresh read never silently ignores a selected installation. Filesystem and fault-injection tests must establish M3–M5 behavior before these planned contracts are reported delivered.

Local binding adapter (2026-09-18): when `InputOptions.adopted` is absent, `readInputs` loads optional `.ia/workspace.json`: `{ "version": 1, "adopted": [{ "id": "foundation", "path": "vendor/foundation", "revision": "<sha256>" }] }`. This closed host-data format supports at most 16 bindings and 64 KiB of UTF-8 JSON. Each path is a canonical portable directory inside the current workspace and outside its `.ia` tree; absolute paths, parent traversal, duplicate IDs/directories and aliases refuse. Only the selected directory's physical `.ia/src` sources are captured, with package artifacts excluded and no recursive binding expansion. Its floor is excluded: the workspace still selects exactly one explicit/local/embedded floor. The revision uses the existing `AdoptedSource` digest of the ordered exact `{path,text}` list. Missing roots, malformed configuration or changed pinned bytes fail the capture; they never silently drop a dependency. Bindings are validated and read in manifest order, each read before the next is validated, so the first faulty binding answers with its own fault, a read-time one (a link, a missing tree, a changed pin) included, as the frozen Door routes and `ia scope` report it. Explicit `adopted` captures, including `[]`, replace automatic bindings. Disk/editor refresh rereads the manifest and dependency bytes; failed refresh retains internal evidence while the host marks it unavailable. Read-only adopted placement, membership, admission and stale-action semantics remain unchanged; this manifest grants no writable system or model disclosure. An adopted mount's sources carry the path `.ia/adopted/<id>/<revision>/<path>`, a label under which no file exists. `adoptedBindings(root)` (2026-10-07) returns the manifest's bindings, frozen, each `{id, path, revision, tree}` with `tree` that label, validated as discovery validates them (the same IA-DB-ROOT-INVALID, IA-DB-SOURCE-UNAVAILABLE and IA-DB-PATH-UNSAFE refusals) without reading or verifying the bound sources, and [] without a manifest, so a host can read a mount's other files, such as the documents `ia read` returns, from its bound directory; those files are outside the revision pin.

Editor extension contract (2026-09-18): `/editor` owns cache-free captured-input readers, versioned unsaved overlays (including local floor buffers), deleted-source reconciliation and privileged source/registry/occurrence inspection. Reads share the existing scope, admission and view implementation; every refresh retires the previous reader. An editor reader retains no previous snapshot (D08). Source metadata identifies embedded/explicit floor as virtual read-only, and local sources by placement/provenance. Existing `Handle.preview` retains its non-floor draft contract. No filesystem writes occur in editor capture or preview. Candidate/baseline comparison preserves unrelated pre-existing failures while refusing new errors or loss of admitted records.

Implementation contract for database plan. Depends on @inventarch/language, @inventarch/graph and @inventarch/compliance. Node filesystem adapter; source parsing and semantic decoding stay in language, graph owns all adjacency/postings, compliance alone constructs verdicts.

D01. open(root, options) reads a canonical existing workspace directory and its .ia/src tree. A missing source tree is empty. Read only regular .ia files and all direct system directories, including empty ones. Refuse symlink/junction source or cache traversal and paths escaping the canonical workspace; never follow an alias into another source root. Canonical source names are workspace-relative and slash-separated. Windows override lookup is case-insensitive and duplicate aliases refuse. Decode UTF-8 fatally while preserving a BOM as source content; invalid encoding or unreadable source is SOURCE-UNAVAILABLE. No source file is written.

D01a. Workspace file bytes (2026-10-08; runtime R12, the Door's `read`). `readWorkspaceBytes(root, path, limit)` returns the exact bytes of one workspace file at the workspace-relative `path`. The path is canonicalized as a source path is; one that escapes the workspace is IA-DB-PATH-UNSAFE and, having no canonical path, carries no `path`. The canonical path must then be portable by the rule the distribution workspace file reader (`ia read`'s) applies, so the two readers admit the same paths: NFC, at most 1024 code units, no backslash, control character or any of `<>:"|?*` (on Windows a colon names an alternate data stream), and no segment that ends in a dot or a space or names a reserved device; one that is not is IA-DB-PATH-UNSAFE. An invalid root is IA-DB-ROOT-INVALID. `safePath` refuses a symbolic link or junction on the way, IA-DB-PATH-UNSAFE, as is a file that is not regular or has a second name (a hard link), as package source capture refuses one. A missing or unreadable file, a path through a file included, or one of more than `limit` bytes, is IA-DB-SOURCE-UNAVAILABLE, and a file replaced or resized while it is read IA-DB-SOURCE-CHANGED. Each of these refusals after canonicalization carries the canonical path as `path`, and its message names no other path, never an absolute one: a filesystem failure keeps only its error code. A `limit` that is not a nonnegative safe integer is a TypeError. At most `limit` + 1 bytes are allocated, and nothing is decoded. It is a host's reader of a document a record names, never admission: it adds no source, snapshot field, cache payload or revision input, and the frozen Door routes do not call it. `tests/inputs.test.ts` pins the exact bytes, either separator, a junction on the way, a hard-linked file, a directory, an escape, a missing file, a path through a file, nine nonportable paths (two of them naming files that exist), the bound and an invalid root, each refusal with its exact message and `path`.

D02. Default authored sources use band100, empty reach and workspace provenance. Local or embedded .ia/src/floor sources use floor10/bootstrap. Explicit per-source Location overrides supply other closed placement/provenance values and canonical reach; validate kind/band consistency. options.floor is an explicit array of canonical floor path/text sources, replacing local/default floor. D02a. Capture membership (position-and-projection row 3). `Snapshot.membership` holds one frozen row `{identity, root, band, digest}` per record in `records`, in the same identity order: `band` is the record's placement band and `digest` its graph G13 per-record digest. The capture declares roots once, from the `@workspace` records the root view (location '', no phase) admits: each `composition.sources` entry spelled `<root> @<placement>` declares that root at that placement, read relative to the tree holding the declaring record (the directory above its `.ia/src`, which the exported `sourceTree(path)` names: '' for the workspace's own tree, a package's or an installed store's directory, and an adopted mount's `.ia/adopted/<id>/<revision>` label), so an adopted or installed `@workspace` speaks only for its own mount. An entry that does not parse, names an unknown placement, or is absolute or escapes that tree declares nothing (`inertDeclarations` names it, D02b), and so does a `@workspace` the root view does not admit (one whose reach excludes the root). A record's `root` is the longest declared root at the record's own placement that contains its source path; the record is then a member of every `@workspace` declaring that root. That is composition, not an edge row or a field index. Any other record keeps its system seat: the `systemMember` system folder of its path, whether local, package, adopted (`.ia/adopted/<id>/<revision>/…`) or installed (`.ia/distributions/store/<archive>/…`). A record under `.ia/src/floor/` is rooted at `.ia/src/floor`, and any other record outside every system folder (the generated installation workspace) at its source directory, so floor records read `.ia/src/floor` at band 10 unless a workspace declares a root containing them at `@floor`. Each view's rows come from its admitted winners: shadowed, tied, blocked, refused and inactive (out-of-reach or out-of-phase) occurrences, and records admission removed, are not admitted records and have no row. A row depends only on its occurrence and the capture's declared roots, so every view admitting an occurrence gives it the same row: a scope narrowed by identities, root or phase prunes rows and never re-roots one, although a narrower root or phase can admit another occurrence of an identity, whose row is its own. The input model cannot express two cases: an adopted closure named by locator (`<distribution-id>@<digest>`, design row 8) is not a path, so such a `sources` entry declares no root and adopted and installed records keep their system seats; and nothing seats a record by anything but its path and placement. Membership and per-record digests are not revision inputs, so workspace revisions are unchanged. The runtime Door's MACHINE_PROTOCOL version 1 `records` operation omits `membership`.

D02b. Location seat (position-and-projection row 17). `resolveSeat(path, options)` on every reader returns a frozen `SeatResolution` `{path, seat?, by?, claimants, unknown?}`. `path` is canonicalized as a scope root with `\` read as `/`; an absolute path, or one escaping the workspace, comes back as supplied with `unknown: 'outside'` and no claimants. Otherwise the seat is the first that applies, and `by` names which: `system`, the admitted `@system` of the system folder that holds the path or is the path, as `systemMember` reads local, package, adopted and installed folders, and the floor's `@system` for `.ia/src/floor`; `root`, the `@workspace` declaring the longest D02a root that contains the path, at any placement, ties by workspace identity; `repository`, for a path with no `.ia` segment, the repository's own `@workspace`. The capture decides that workspace once, from the root view, as the one admitted `@workspace` in the repository's `.ia/src` tree that declares a root, else the only `@workspace` there; none or several decide none. With no seat, `unknown` is `undeclared`. `claimants` are graph G06c's claimants of the path, whatever the seat: each record whose `authority.covers`, `subject.covers`, `work.covers` or `hook.paths` selection selects it (a `@check`'s prose `check.scope` claims nothing), with every matching field and selection, band descending then identity ascending; the graph indexes the selections once per load, so claimants are read from that index, never from the records, and the seat from the graph's name and discriminator indexes and the capture's declared roots. `options` bind as `get` binds them (CLOSED, STALE, SCOPE-UNAVAILABLE, SCOPE-MISMATCH), and a scope prunes as search and resolution do (D09): a seat or claimant outside it is absent, so the path takes the next seat that applies. `inertDeclarations(options)` on every reader names, as frozen `{identity, field, value, path, line, reason}` values ordered by path, line and identity and pruned to the scope, each declaration the capture reads that declares nothing: a `composition.sources` entry of an admitted `@workspace` that names no root (D02a), and a claimant selection the dialect reads as none (graph `isSelection`), which selects no path, so a host can say so where it is authored; neither is a report finding, so admission, snapshots and the Door are unchanged. The resolution reads the view's graph and the capture's declared roots only; it adds no snapshot field, no cache payload beyond the graph's G06c index and no revision input, and the frozen Door routes and `ia scope` do not call it. `tests/seat.test.ts` pins the exit evidence (`.ia/src/systems/work-system/records/work.ia` seats at work-system with the fixture `@mandate` that covers it), each seat rule and the root tie-break, how the repository's own `@workspace` is chosen, outside paths, claimant order across bands and fields, scope binding and a scope pruning each seat rule, and the editor reader's unsaved overlays.

D02c. Declared roots (position-and-projection row 3; runtime R15). `roots(options)` on every reader returns the roots the capture declares (D02a) as frozen `DeclaredRoot` copies `{root, placement, workspace}`, in the capture's order: longest root first, then by declaring `@workspace` identity. An entry that declares nothing (`inertDeclarations`) is no root. `options` bind as `get` binds them (CLOSED, STALE, SCOPE-UNAVAILABLE, SCOPE-MISMATCH), and a root whose declaring `@workspace` the read does not admit is pruned, as the seat rule prunes it (D02b, D09); membership rows keep the roots they were captured under whatever the scope, so pruning a root never re-roots a row. It is how a runtime reader computes a workspace's capture members and closure without the private view: it adds no snapshot field, cache payload or revision input, never reads the D08a capture pair, and the frozen Door routes do not call it. `DeclaredRoot` is exported as a type. `tests/membership.test.ts` pins the order, the inert entry left out, frozen copies, and a scope that does not admit the declaring workspace pruning its roots while its rows keep theirs; `tests/scope.test.ts` and `tests/retention.test.ts` pin the token checks and that no capture file is read.

D03. A source snapshot includes all selected source bytes, paths, placement/provenance and discovered system folders. A derived revision-only input carries the folder inventory, floor origin and admission-policy version so empty-folder changes also change the revision; it is never parsed or exposed as an authored record. A view selects sources by reach before building its registry, compiles them independently through language, and delegates authority/phase and external resolution to graph. Never pass all shadowed external occurrences to the compiler as an ambiguous pool. Preserve language section11.2: any language error refuses every record in that file; healthy other files remain independent. Compiled preview siblings are never promoted to admission. Whole-tree requirement ids remain unique without a band exception under language S09. Before authority can hide duplicates, collect distinct physical requirement occurrences from error-free compilation at every distinct declared reach (and the requested location), using each location's registry. Deduplicate the same source occurrence across views, then invoke the shared language collision helper; every participating file is refused. This finite context set covers all registry visibility changes without inventing a second requirement parser.

D04. Compliance validates candidate schemas and system joins. A malformed system folder or missing steward refuses that join, its owned words and dependent systems; preserve the root finding. Foreign instances, invalid schemas, selectors, variants and unknown check runners are not readable admitted nodes. A schema assessment that remains not-evaluated cannot establish instance admission. Rebuild graph relationships after removing refused nodes until admission stabilizes; retain failed/unavailable assessments as admission evidence without turning earlier candidate passes into final claims. Coverage/adoption failures remain report evidence and do not erase an otherwise structurally valid contract/workspace declaration. The public snapshot identifies admitted system order and refused subjects separately from candidate vocabulary; private graph registry data is not exposed as admission proof.

D05. The root view revision is the handle's whole-source generation stamp; graph revisions additionally include the effective view registry. Every selected source participates even when unreachable in a view. Refresh fully rereads and rebuilds; system/schema changes always rebuild everything. Verify source discovery/bytes are stable before publishing a new snapshot, retry a bounded three times on concurrent changes, then SOURCE-CHANGED. Publication swaps the complete immutable state; failed refresh preserves the previous state. Source errors produce attributable partial admission, not silent success.

D06. The derived .ia/.iadb/graph.json stores a format tag, revision and deterministic serialized root graph. Always build/validate fresh and compare the complete payload before accepting a cached artifact; a matching stamp alone is insufficient. Equal bytes are not rewritten. Changed/corrupt/foreign bytes are replaced atomically through a unique same-directory temporary file. Recheck containment immediately before access/publication. Cache I/O failures produce CACHE-UNAVAILABLE and leave the valid in-memory snapshot usable; no authored file is touched. This version saves redundant writes, not parsing work. Fresh/cached/refreshed graphs are byte-equal for equal inputs. `cache.state` and `cache.observations` report this file alone; the D08 retained pair is the capture pair of D08a, never a cache file.

D07. resolveScope issues an opaque unguessable token bound privately to its issuing handle, canonical root, optional phase (wildcard when omitted), view revision and source generation. The initial occurrence boundary includes every reachable candidate occurrence before phase selection; an optional identity allowlist only intersects it. A child root is the same or a segment-boundary descendant. Its occurrence boundary intersects the parent's and its admitted identities include only winners whose actual occurrence is in that boundary. A new winner with the same identity cannot widen it. A child may change phase but never add occurrences. Omitted child bindings inherit; explicit phase:null requests a wildcard. Refuse narrowing with SCOPE-MISMATCH if the effective registry differs from the parent: a read token cannot authorize new vocabulary/schema interpretation. A privileged host may issue an independent root token for that view. Explicit requested revision must agree with the inherited token when narrowing.

D08. Every read carrying a token validates issuer, open state, generation and explicit root/phase/revision assertions. Omitted bindings inherit. Unknown/forged/other-handle tokens are SCOPE-UNAVAILABLE; incompatible bindings or a wider child root SCOPE-MISMATCH; changed generation STALE (a token never revives after refresh to different inputs and back); closed handle CLOSED. Stale tokens never read current bytes under an old stamp. Scope grants reading only. Tokens are not transferable between processes without the later owning transport retaining their issuing handle.

D08 retention (position-and-projection row 20), apart from scope validation: a handle retains two admitted root snapshots, seeded from the capture pair of D08a (location '', no phase), each as its revision and D02a membership rows: the current one, and `previous`, the most recent admitted root snapshot whose revision differs from the current one. Only a revision change rotates. A refresh, or a new handle, that finds the revision last retained as current keeps the existing previous, so a plain open or refresh at an unchanged revision never wipes the comparison that staleness and readiness depend on; a revision change, even one that alters no record text, rotates that current into previous; a failed refresh rotates nothing. `previousRevision` names the previous snapshot, undefined while none is retained. `staleness(identity, options)` and `readiness(identity, digest, options)` bind `options` exactly as `get` does (CLOSED, STALE, SCOPE-UNAVAILABLE, SCOPE-MISMATCH, and OUT-OF-SCOPE for an identity outside the scope's allowed identities) and take the current digest from the view `get` reads, so their current side is the record `get` returns. Only root snapshots are retained, so the previous side is the identity's digest in the previous root snapshot, and it applies only while the selected view's digest is the identity's current root digest, as it always is for a root read. `staleness` answers `unchanged` when the two sides are equal, `changed` when not, `new` when only the current side has a digest (so every current identity reads `new` while no previous snapshot is retained), `removed` when only the previous side does, undefined when neither does. `readiness` answers `current` when `digest` equals the current side, else `previous` when it equals the previous side, else `unknown`: digest equality, never an order. When a narrower root or phase selects a digest other than the current root one, including a record only one of the two views holds (for example a phase-shadowed or tied occurrence, or one only a narrower root reaches), the retained root snapshots describe a different occurrence: `staleness` is undefined and `readiness` answers `current` for the selected record's own digest, else `unknown`. A scope admits only identities its view holds, so a read through a scope token never reports `removed`. The previous snapshot persists between processes as the capture pair of D08a, the one retained pair, which only `ia capture` writes: every disk handle, whatever its cache setting, seeds its pair from it, and no handle writes it. A handle reads the pair the first time it is asked for `previousRevision`, `capturedRevision`, `staleness` or `readiness`, never on open or refresh, so a read that never asks (every frozen Door route) opens no capture file. The seed is the capture at `current.json` and, when it is a capture at another revision, the one at `previous.json`; with no readable `current.json`, a capture at `previous.json` alone. The handle rotates that seed against its own root snapshot: at the captured revision `previous` is the capture at `previous.json`, at another revision it is the capture at `current.json`. A `current.json` that names the fresh revision with other membership rows is not this workspace's capture at that revision, so the pair seeds nothing; a capture at another revision cannot be rebuilt from the fresh inputs, so it is trusted as written. A link or junction on the way, an entry that is not a regular file, and a file that is no capture (not JSON, another format, a malformed revision or membership row) are ignored, never followed, and leave every read usable. `capturedRevision` names the revision of the capture at `current.json`, undefined when there is none or it is not trusted; a capture at another revision than `revision` is stale. A refresh rotates the pair its handle holds in memory without reading the capture pair: at a changed revision the root snapshot it held becomes `previous`, and at an unchanged one it keeps the previous side it held, still unread until asked, so however often a handle refreshes it holds one pair. `capturedRevision` is read again the next time it is asked after a refresh, as `ia capture` may have run, so a handle that lived through an edit reports the edit as changed whether or not it was captured. The cache-free editor reader retains nothing: `previousRevision` and `capturedRevision` are undefined, every current identity reads `new`, and `readiness` never answers `previous`. Retention is not a revision input and adds no snapshot field, so workspace revisions, snapshots and the Door's MACHINE_PROTOCOL version 1 output are unchanged.

D08a. The capture pair (position-and-projection §5 and rows 3 and 20). `writeCapture(root, text)` writes `text`, an `ia-snapshot-1` document (`CAPTURE_FORMAT`: one JSON object whose `format` is `ia-snapshot-1`, whose `revision` is a 64-hex workspace revision and whose `membership` holds D02a rows, each exactly `{identity, root, band, digest}` with a closed band and a 64-hex digest, identities unique), to `.ia/work/snapshot/current.json` (`CAPTURE_CURRENT`), keeps `.ia/work/snapshot/previous.json` (`CAPTURE_PREVIOUS`) as D08 rotates its pair, and returns `{prior, ignored, previous, rotated, changed, unchanged, added, removed}`; any other `text` throws a TypeError before anything is touched. Its counts follow `staleness` against the prior capture at `current.json`: an equal digest is unchanged, another changed, a row the prior lacks added, and a prior row with none now removed; with no readable prior capture every row is added, and `ignored` says why an existing `current.json` was not taken as one. A capture at a new revision makes the prior `current.json` the new `previous.json`, renamed, so byte for byte; one at an unchanged revision keeps `previous.json` while it holds a capture at another revision; with no readable prior capture, a `previous.json` at another revision is kept as the most recent capture there is; a `previous.json` at the new revision, or one that is no capture, is moved aside before `current.json` is written and removed after; and a `current.json` that already holds `text` is not rewritten. Nothing is written until every check passes: a link or junction on the way, an entry at `.ia`, `.ia/work` or `.ia/work/snapshot` that is not a directory, or an entry at either path that is not a regular file, refuses as PATH-UNSAFE; for an entry that is not a directory or not a regular file the error's optional `path` names it, and a link or junction is named in the message. The new bytes are staged first in a unique same-directory temporary file, flushed and owner-only; a rotation then moves `previous.json` aside, renames `current.json` to `previous.json` and the staged file to `current.json`, and a step that fails undoes the ones before it in reverse, so a failed write leaves the pair it found and only the error escapes (a process killed between two renames can leave the moved-aside file and `previous.json` holding what `current.json` held, which the next capture rotates again). Concurrent captures of one root are last-writer-wins. The pair is local working state under `.ia/work/`, never a source and never read by admission, and no handle writes it.

D08b. The capture plan (decision capture-preview-placement; `ia capture --preview`). `planCapture(root, text)` makes every check and read `writeCapture(root, text)` makes before its first write, with the same TypeError for a `text` that is no `ia-snapshot-1` document and the same PATH-UNSAFE refusals, and returns the frozen `CapturePlan`: the result that write would return, so its counts, `prior`, `ignored`, `previous` and `rotated` are the write's, plus `identities` `{changed, added, removed}`, the identities those three counts count, each list sorted by code unit (with no readable prior capture, `added` lists every row). It creates no directory and stages, renames, removes or writes no file, so the capture pair keeps its bytes and modification times. `writeCapture` makes its checks and reads through the same planner, then writes; its result and its writes are unchanged. `CapturePlan` is exported as a type. `tests/retention.test.ts` pins the plan of a workspace never captured (no `.ia/work` is created), one edit named as the one changed identity with the pair left as it was, an added and a removed identity, the plan agreeing with the write's result at each step, a check that refuses the plan, and each list sorted by code unit whatever order either document holds its rows in.

D09. get, records, referencedBy, directedView, resolveSeat, words, roots, resolve, search and traverse honor the supplied token and view. get, referencedBy and directedView, like D08 staleness and readiness, yield OUT-OF-SCOPE outside their allowed identities; referencedBy returns graph G06a typed field references naming the identity, pruned to holders in scope; directedView returns the identity's graph G06b directed view (its declared edge rows, the derived inverses of its counterparts' declarations and its typed field references both ways, each row with `declaredOn`, its spelling or field path and `derived`), pruned the same way to rows whose counterpart is in scope (the declaring record is the identity or that counterpart, so a pruned scope never shows a row declared outside it). The view is the position-and-projection row 4 snapshot derivation: graph computes it on read from the view's admitted graph, so it is per revision and deterministic but is not stored in the cache payload or the D08a capture and is not a revision input. Row 4 places the derived view in the admitted snapshot, computed at capture and owned by db; this computes the same pure function of one revision where it is read, which a capture document need not carry. Dangling, ambiguous and consent-refused assertions stay admission findings (graph diagnostics in the report) with no row in it; lists/search/resolution, D02b seat resolution included, prune and traversal cannot cross an excluded intermediary. Scope and typed traversal filters apply before emitting gated edges. A scoped snapshot exposes only allowed immutable nodes, their D02a membership rows, its root/phase/view revision and admitted system order; it does not expose the private full graph/registry/indexes or unscoped diagnostics. All query products delegate to graph; db creates no second adjacency or text index. Unscoped reads are privileged host inspection, and runtime must always supply a token.

D09a. Registered words (position-and-projection row 10). `words(options)` on every reader returns the frozen, sorted keywords the read view's registry registers for its admitted systems, the floor's `system` and `schema` included; a keyword two systems register at the winning band is blocked and absent, and so is every word of a system admission blocked. It is the closed set a runtime scope key's `word` is checked against (runtime R14). `options` bind as `get` binds them; a scope narrows records, never the registry (a child scope that would change it refuses, D07), so every scope of a view reads the same words. Only the keywords are exposed: the registry, its registrations and its consent ledgers stay private. ### Explicit package-local authored inputs (OS06 U01 prerequisite)

`InputOptions.authoredRoots` selects a frozen, sorted list of repository-relative package directories. Selection is explicit host input; the database does not discover a monorepo, inherit a parent workspace, or read package policy JSON. Each selected directory contributes only its `.ia/src/systems/<owner>/` native files, at authored workspace precedence and with the original physical `source.path`. Vocabulary identities are unchanged. The sole system declaration remains at the repository root; a package cannot carry its own system declaration, floor, workspace/adoption manifest, distribution lock, release manifest, or legacy package authority. Existing structural admission and duplicate diagnostics apply across the combined source set.

Directories must be portable, canonical, disjoint and unaliased. The reader refuses junctions/symlinks, hard-linked native files, nonregular sources, invalid UTF-8, missing root system context and ambiguous path spellings. Selected package capture is bounded to 1000 package roots, 20000 native files, 1 MiB per file and 64 MiB aggregate native bytes. Reads allocate at most the statted size plus one byte and refuse concurrent size/metadata changes. Hosts must additionally bound their full repository capture and verify inventory membership, package-to-record correspondence, ownership, policy/evaluator freshness and one writer.

Selection and exact source bytes participate in the input fingerprint and admitted revision. Refresh therefore invalidates previous scopes when a selected package source changes. A contextual scoped read uses the root handle; opening a package directory alone supplies no parent definitions and does not admit those instances. No package-local editor write or preview target is added: existing draft paths remain root `.ia/src` paths. This is the upstream read prerequisite, not a claim that a consuming monorepo has completed its package-record cutover or installed qualification.
