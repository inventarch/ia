## Runner journal evidence

Event IDs are session command IDs: an atomic command may contribute up to 32 contiguous events with the same ID, actor and cause. Noncontiguous reuse, changed command attribution, and oversized command groups are rejected. Sequence and hash chaining identify each distinct event. Exact runner authority and limit refusal waits project refusal; unrelated waits remain inconclusive.

`writeRunnerEvidence(root, {authoredRevision, events})` records a verified runner journal as closed JSON under `.ia/work/runner-evidence/<authored revision>-<SHA-256 session id>.json`. The caller first reads the journal through session-system; DB checks the bounded transport and event hash chain, never duplicates the session transition reducer. It accepts no native source text. The optional reader uses the same `evidence: true` option as D14, lists at most 128 receipts, and reads only the current authored revision's receipts, at most 4 MiB and 4,096 events each and 16 MiB in total. UTF-8, duplicate keys, fields, versions, sequence, session identity, event hashes, creation and manifest hashes are checked. Every creation or rebind must name the current whole-workspace capture digest with capture id `runner`, using the exact reader-selected sources, folders, floor origin and activation. Explicit host input options therefore remain effective. Stale, malformed, linked, oversized or changed receipts are ignored.

The view generates only `@run` and `@observation` at runtime band 0. A run is named `runner-<SHA-256 session id>` and its owner is the unique admitted agent referenced by the creation profile's `composition.agent`. Its status and phase are `recorded`: this is a journal projection, not live engine state. Root operation observations, root accepted outcomes and root waits become observations with `evidence.subject @run`; an operation's unknown or partial effect is inconclusive, a limit wait records refusal without implying termination, and accepted outcomes retain refusal even when terminal status is completed. Payload prose cannot add native declarations or relationships. Authored-name collisions refuse the receipt, and adding generated sources must leave existing records, findings, verdicts and refusals unchanged. D14's exact validation-evidence reproduction is independent and unchanged. Evidence changes the reader revision, never the authored revision; existing evidence-free readers and caches remain unchanged.

Journal hashes establish internal integrity, not an external observer, authorized execution, event truth, trustworthy timestamps or successful real-world effects. A party that can replace a whole local journal can produce another consistent claim; these receipts grant no authority and no executable implementation. Session transition validation and current execution status remain session-system and runner responsibilities. The projection records no new authority-bearing words, claims or governing relationships.

The writer validates data without evaluating accessors and atomically stages, flushes and replaces a receipt under a per-receipt exclusive lock. It rejects an older or divergent prefix instead of overwriting it, and never prunes other sessions or revisions. A held or abandoned `.json.lock` refuses; recovery requires establishing that no writer owns it before manually removing that exact lock. Rollback consists of removing the selected receipt after its writer stops; the source journal and authored files are unchanged. Removing a receipt removes only its optional projection. `tests/runner-evidence.test.ts` exercises ordinary and editor admission, subject references, existing validation evidence, successful operations, limit refusal, terminal outcomes, stale/colliding/tampered data, source rebinding, data accessors, bounded reads and unsafe paths. Session replay and actual operation execution are qualified by the runner integration tests.

Bounded repository capture: a host that captures package-local sources selects them explicitly with `InputOptions.authoredRoots` (Explicit package-local authored inputs, below) through the public admission interfaces. It does not change this package's root discovery or adoption limits, and it adds no implicit parent or recursive scanning. Native revision and full code/toolchain identity remain distinct.

## Descriptor producer

The public `@inventarch/db/descriptors` entrypoint owns the pure, bounded, versioned codecs and compilers for `domain-model`, `storage-binding` and `app-composition` resources: strict 1 MiB/depth-16/1,000-entry JSON with duplicate-key refusal, canonical `sha256:` digests bound to the native envelope, a host-built trusted contract registry for command/query/validator/view/operation/port/adapter/migration-policy IDs, and typed single-diagnostic refusals with owner/source/resource/field attribution. It performs no I/O, DDL or code execution, and the three words remain unregistered; an isolated candidate is admitted only through `preview`. The strict JSON transport is shared with the distribution codec through `src/json.ts` with unchanged distribution messages. See the [descriptor SPEC](src/descriptors/SPEC.md).

## Distribution implementation packet

The public `@inventarch/db/distribution` entrypoint owns strict version-1 transport decoders and canonical bytes for release descriptors/manifests, portable locks, generation membership and activation pointers. JSON rejects duplicate decoded keys and unknown fields; object input must be bounded plain data without accessors or aliases. Native parsing stays in language. Package IDs are provider-qualified lowercase `provider/name`; versions and ranges use pinned SemVer. No absolute path or credential enters a portable lock. Metadata limits are 4 MiB, 128 selected bundles and 10,000 files, beside separate archive/file ceilings. Decoding copies and freezes output. A release descriptor's `distribution` is its one optional key (2026-10-09): a workspace that releases nothing, as one a default `ia init` creates, omits it, and the decoded `ReleaseDescriptor` then has no `distribution` property; present, it must still be a native distribution identity, never null. A bundle manifest always carries one, and its decoded keys keep their order, so canonical bytes are unchanged.

The same entrypoint shapes the installed-implementation catalog a host payload carries: `checkInstalledImplementations(value)` admits exactly `format` `ia.installed-implementations.v1`, an `evaluators` section with an `ia-evaluator-catalog/1.x` format and at most 1,024 entries, and at most 1,024 `operations` sorted by id and unique, each `available` (id, version, operation identity, handler, input and output validator ids, a portable `runtime/node_modules/...` handler module inside one of its sorted `packages`, and the module's SHA-256), `unavailable` or `revoked` with a single-line reason, and returns the value or the first reason it is not one; it reads, loads and executes nothing. `@inventarch/distribution` verifies a catalog against its payload with it and `@inventarch/workspace-runtime` binds records against its rows (`InstalledOperation`).

Generation membership enumerates selected bundle IDs/archive digests and source inventories derived from verified manifests, with deterministic identical-system deduplication and contributing-package provenance. Readers verify complete file inventory, exact canonical generation bytes and the active lock, and load only selected source bytes. An unpinned regular file named `.DS_Store` or `._*`, which a Mac writes into directories it opens, is skipped; a pinned one is verified like any other, and a link or special file of such a name is refused (`platformDebris`). Candidate installation is an explicit host-selected input option; it does not bypass admission or grant writes. The generated installation workspace uses native composition and direct-distribution use edges. Installed sources retain adopted band 90/methodology; generated installation state uses band 100/workspace. Active generation and monotonic counter participate in revision and scope freshness. Existing authored/adopted callers keep their behavior when no installation exists.

Root release-control sources at `.ia/src/releases/<distribution-name>.ia` contain exactly their selected public distribution declaration, meaning and unconditional system roots matching the manifest. The shared `verifyReleaseControl` check enforces this source profile in archive verification, expanded-bundle reads and `generationSources`, including retained source installations whose content and metadata have been consistently repinned. Ordinary system-source admission remains a separate check.

The application owns archive acquisition, bounded solving and mutation. The database owns no network or installation writes. Restore-required, lock-drift, corrupt-state, recovery-required and engine-incompatible are named `InstallationError` reasons, each with code IA-DB-SOURCE-UNAVAILABLE; a fresh read never silently ignores a selected installation.

Local binding adapter (2026-09-18): when `InputOptions.adopted` is absent, `readInputs` loads optional `.ia/workspace.json`: `{ "version": 1, "adopted": [{ "id": "foundation", "path": "vendor/foundation", "revision": "<sha256>" }] }`. This closed host-data format supports at most 16 bindings and 64 KiB of UTF-8 JSON. Missing roots, malformed configuration or changed pinned bytes fail the capture; they never silently drop a dependency. Bindings are validated and read in manifest order, each read before the next is validated, so the first faulty binding answers with its own fault, a read-time one (a link, a missing tree, a changed pin) included, as the frozen Door routes and `ia scope` report it. Explicit `adopted` captures, including `[]`, replace automatic bindings. Disk/editor refresh rereads the manifest and dependency bytes; failed refresh retains internal evidence while the host marks it unavailable. Read-only adopted placement, membership, admission and stale-action semantics remain unchanged; this manifest grants no writable system or model disclosure. D01. open(root, options) reads a canonical existing workspace directory and its .ia/src tree. A missing source tree is empty. Read only regular .ia files and all direct system directories, including empty ones. Refuse symlink/junction source or cache traversal and paths escaping the canonical workspace; never follow an alias into another source root. Canonical source names are workspace-relative and slash-separated. Windows override lookup is case-insensitive and duplicate aliases refuse. Decode UTF-8 fatally while preserving a BOM as source content; invalid encoding or unreadable source is SOURCE-UNAVAILABLE. No source file is written.

D01a. Workspace file bytes (2026-10-08; runtime R12, the Door's `read`). `readWorkspaceBytes(root, path, limit)` returns the exact bytes of one workspace file at the workspace-relative `path`. The path is canonicalized as a source path is; one that escapes the workspace is IA-DB-PATH-UNSAFE and, having no canonical path, carries no `path`. The canonical path must then be portable by the rule the distribution workspace file reader (`ia read`'s) applies, so the two readers admit the same paths: NFC, at most 1024 code units, no backslash, control character or any of `<>:"|?*` (on Windows a colon names an alternate data stream), and no segment that ends in a dot or a space or names a reserved device; one that is not is IA-DB-PATH-UNSAFE. An invalid root is IA-DB-ROOT-INVALID. `safePath` refuses a symbolic link or junction on the way, IA-DB-PATH-UNSAFE, as is a file that is not regular or has a second name (a hard link), as package source capture refuses one. A missing or unreadable file, a path through a file included, or one of more than `limit` bytes, is IA-DB-SOURCE-UNAVAILABLE, and a file replaced or resized while it is read IA-DB-SOURCE-CHANGED. Each of these refusals after canonicalization carries the canonical path as `path`, and its message names no other path, never an absolute one: a filesystem failure keeps only its error code. A `limit` that is not a nonnegative safe integer is a TypeError. The file is opened read-only before its type, link count and size determine admission or allocation. Metadata and bytes come from that descriptor; the named file and containing directory identities are checked before and after reading, along with the handle's size, link count and timestamps. All identity and timestamp metadata uses bigint stats, retaining file IDs above JavaScript's safe-integer range. At most `limit` + 1 bytes are allocated, and nothing is decoded. It is a host's reader of a document a record names, never admission: it adds no source, snapshot field, cache payload or revision input, and the frozen Door routes do not call it. `tests/inputs.test.ts` pins the exact bytes, either separator, a junction on the way, a hard-linked file, a directory, an escape, a missing file, a path through a file, nine nonportable paths (two of them naming files that exist), the bound and an invalid root, each refusal with its exact message and `path`. Injected after-open file replacement, hard-link creation and parent replacement refuse before reading; mid-read growth is bounded and refused, and each opened handle is closed.

D02a. Capture membership. `Snapshot.membership` holds one frozen row `{identity, root, band, digest}` per record in `records`, in the same identity order: `band` is the record's placement band and `digest` its graph G13 per-record digest. The capture declares roots once, from the `@workspace` records the root view (location '', no phase) admits: each `composition.sources` entry spelled `<root> @<placement>` declares that root at that placement, read relative to the tree holding the declaring record (the directory above its `.ia/src`, which the exported `sourceTree(path)` names: '' for the workspace's own tree, a package's or an installed store's directory, and an adopted mount's `.ia/adopted/<id>/<revision>` label), so an adopted or installed `@workspace` speaks only for its own mount. An entry that does not parse, names an unknown placement, or is absolute or escapes that tree declares nothing (`inertDeclarations` names it, D02b), and so does a `@workspace` the root view does not admit (one whose reach excludes the root). A record's `root` is the longest declared root at the record's own placement that contains its source path; the record is then a member of every `@workspace` declaring that root. That is composition, not an edge row or a field index. Any other record keeps its system seat: the `systemMember` system folder of its path, whether local, package, adopted (`.ia/adopted/<id>/<revision>/…`) or installed (`.ia/distributions/store/<archive>/…`). A record under `.ia/src/floor/` is rooted at `.ia/src/floor`, and any other record outside every system folder (the generated installation workspace) at its source directory, so floor records read `.ia/src/floor` at band 10 unless a workspace declares a root containing them at `@floor`. Each view's rows come from its admitted winners: shadowed, tied, blocked, refused and inactive (out-of-reach or out-of-phase) occurrences, and records admission removed, are not admitted records and have no row. A row depends only on its occurrence and the capture's declared roots, so every view admitting an occurrence gives it the same row: a scope narrowed by identities, root or phase prunes rows and never re-roots one, although a narrower root or phase can admit another occurrence of an identity, whose row is its own. The input model cannot express two cases: an adopted closure named by locator (`<distribution-id>@<digest>`) is not a path, so such a `sources` entry declares no root and adopted and installed records keep their system seats; and nothing seats a record by anything but its path and placement. Membership and per-record digests are not revision inputs, so workspace revisions are unchanged. The runtime Door's MACHINE_PROTOCOL version 1 `records` operation omits `membership`.

D02b. Location seat. `resolveSeat(path, options)` on every reader returns a frozen `SeatResolution` `{path, seat?, by?, claimants, unknown?}`. `path` is canonicalized as a scope root with `\` read as `/`; an absolute path, or one escaping the workspace, comes back as supplied with `unknown: 'outside'` and no claimants. Otherwise the seat is the first that applies, and `by` names which: `system`, the admitted `@system` of the system folder that holds the path or is the path, as `systemMember` reads local, package, adopted and installed folders, and the floor's `@system` for `.ia/src/floor`; `root`, the `@workspace` declaring the longest D02a root that contains the path, at any placement, ties by workspace identity; `repository`, for a path with no `.ia` segment, the repository's own `@workspace`. The capture decides that workspace once, from the root view, as the one admitted `@workspace` in the repository's `.ia/src` tree that declares a root, else the only `@workspace` there; none or several decide none. With no seat, `unknown` is `undeclared`. `claimants` are graph G06c's claimants of the path, whatever the seat: each record whose `authority.covers`, `subject.covers`, `work.covers`, `hook.paths` or `check.covers` selection selects it (a `@check`'s textual `check.scope` claims nothing), with every matching field and selection, band descending then identity ascending; the graph indexes the selections once per load, so claimants are read from that index, never from the records, and the seat from the graph's name and discriminator indexes and the capture's declared roots. `options` bind as `get` binds them (CLOSED, STALE, SCOPE-UNAVAILABLE, SCOPE-MISMATCH), and a scope prunes as search and resolution do (D09): a seat or claimant outside it is absent, so the path takes the next seat that applies. `inertDeclarations(options)` on every reader names, as frozen `{identity, field, value, path, line, reason}` values ordered by path, line and identity and pruned to the scope, each declaration the capture reads that declares nothing: a `composition.sources` entry of an admitted `@workspace` that names no root (D02a), and a claimant selection the dialect reads as none (graph `isSelection`), which selects no path, so a host can say so where it is authored; neither is a report finding, so admission, snapshots and the Door are unchanged. The resolution reads the view's graph and the capture's declared roots only; it adds no snapshot field, no cache payload beyond the graph's G06c index and no revision input, and the frozen Door routes and `ia scope` do not call it. `tests/seat.test.ts` pins the exit evidence (`.ia/src/systems/work-system/records/work.ia` seats at work-system with the fixture `@mandate` that covers it), each seat rule and the root tie-break, how the repository's own `@workspace` is chosen, outside paths, claimant order across bands and fields, scope binding and a scope pruning each seat rule, and the editor reader's unsaved overlays.

D08. Every read carrying a token validates issuer, open state, generation and explicit root/phase/revision assertions. Omitted bindings inherit. Unknown/forged/other-handle tokens are SCOPE-UNAVAILABLE; incompatible bindings or a wider child root SCOPE-MISMATCH; changed generation STALE (a token never revives after refresh to different inputs and back); closed handle CLOSED. D08 retention, apart from scope validation: a handle retains two admitted root snapshots, seeded from the capture pair of D08a (location '', no phase), each as its revision, its authored revision (D05a) and its D02a membership rows: the current one, and `previous`, the most recent admitted root snapshot whose authored revision differs from the current one. Only an authored revision change rotates (2026-10-09: a change to runtime-band sources alone, such as evidence an `ia validate` writes, moves the revision but must not spend the comparison staleness and readiness depend on). A refresh, or a new handle, that finds the authored revision last retained as current keeps the existing previous, so a plain open or refresh at an unchanged authored revision never wipes that comparison; an authored revision change, even one that alters no record text, rotates that current into previous; a failed refresh rotates nothing. `previousRevision` and `previousAuthoredRevision` name the previous snapshot's revision and authored revision, undefined while none is retained. `staleness(identity, options)` and `readiness(identity, digest, options)` bind `options` exactly as `get` does (CLOSED, STALE, SCOPE-UNAVAILABLE, SCOPE-MISMATCH, and OUT-OF-SCOPE for an identity outside the scope's allowed identities) and take the current digest from the view `get` reads, so their current side is the record `get` returns. Only root snapshots are retained, so the previous side is the identity's digest in the previous root snapshot, and it applies only while the selected view's digest is the identity's current root digest, as it always is for a root read. `staleness` answers `unchanged` when the two sides are equal, `changed` when not, `new` when only the current side has a digest (so every current identity reads `new` while no previous snapshot is retained), `removed` when only the previous side does, undefined when neither does. `readiness` answers `current` when `digest` equals the current side, else `previous` when it equals the previous side, else `unknown`: digest equality, never an order. When a narrower root or phase selects a digest other than the current root one, including a record only one of the two views holds (for example a phase-shadowed or tied occurrence, or one only a narrower root reaches), the retained root snapshots describe a different occurrence: `staleness` is undefined and `readiness` answers `current` for the selected record's own digest, else `unknown`. A scope admits only identities its view holds, so a read through a scope token never reports `removed`. The previous snapshot persists between processes as the capture pair of D08a, the one retained pair, which only `ia capture` writes: every disk handle, whatever its cache setting, seeds its pair from it, and no handle writes it. A handle reads the pair the first time it is asked for `previousRevision`, `previousAuthoredRevision`, `capturedRevision`, `capturedAuthoredRevision`, `staleness` or `readiness`, never on open or refresh, so a read that never asks (every frozen Door route) opens no capture file. The seed is the capture at `current.json` and, when it is a capture at another authored revision, the one at `previous.json`; with no readable `current.json`, a capture at `previous.json` alone. The handle rotates that seed against its own root snapshot: at the captured authored revision `previous` is the capture at `previous.json`, at another authored revision it is the capture at `current.json`. A capture is trusted by its authored revision and the membership rows of its records not at runtime placement (band other than 0), each by its identity, band and digest: a `current.json` that names the fresh authored revision with other such rows is not this workspace's capture at that revision, so the pair seeds nothing, while one that differs from the fresh snapshot only in its runtime-band rows, and so in its revision, or in the roots of its rows, which a runtime-band `@workspace` can declare (D02a) and no retained read takes, is this workspace's. Admission still reads every placement, so a runtime-band record that changes which records not at runtime placement are admitted (one repeating an authored requirement id refuses both) leaves a capture at that authored revision untrusted until the next capture; a capture at another authored revision cannot be rebuilt from the fresh inputs, so it is trusted as written. A link or junction on the way, an entry that is not a regular file, and a file that is no capture (not JSON, another format, a malformed revision, authored revision or membership row) are ignored, never followed, and leave every read usable. `capturedRevision` and `capturedAuthoredRevision` name the revision and the authored revision of the capture at `current.json`, undefined when there is none or it is not trusted; a capture at another authored revision than `authoredRevision` is stale, and one that differs only in runtime-band sources is not. A refresh rotates the pair its handle holds in memory without reading the capture pair: at a changed authored revision the root snapshot it held becomes `previous`, and at an unchanged one it keeps the previous side it held, still unread until asked, so however often a handle refreshes it holds one pair. `capturedRevision` and `capturedAuthoredRevision` are read again the next time they are asked after a refresh, as `ia capture` may have run, so a handle that lived through an edit reports the edit as changed whether or not it was captured. The cache-free editor reader retains nothing: `previousRevision`, `previousAuthoredRevision`, `capturedRevision` and `capturedAuthoredRevision` are undefined, every current identity reads `new`, and `readiness` never answers `previous`. Retention is not a revision input and adds no snapshot field (the `authoredRevision` a snapshot carries is its view's, D05a), so workspace revisions, snapshots and the Door's MACHINE_PROTOCOL version 1 output are unchanged by it.

D08a. The capture pair (the CLI's `capture`). `writeCapture(root, text)` writes `text`, an `ia-snapshot-1` document (`CAPTURE_FORMAT`: one JSON object whose `format` is `ia-snapshot-1`, whose `revision` is a 64-hex workspace revision, whose optional `authoredRevision` is its 64-hex authored revision (D05a; `ia capture` writes it, and a document without one, written before it, names its `revision` as its authored revision, which it was while no source sat at runtime placement; another value, `null` included, is no capture) and whose `membership` holds D02a rows, each exactly `{identity, root, band, digest}` with a closed band and a 64-hex digest, identities unique), to `.ia/work/snapshot/current.json` (`CAPTURE_CURRENT`), keeps `.ia/work/snapshot/previous.json` (`CAPTURE_PREVIOUS`) as D08 rotates its pair, and returns `{prior, ignored, previous, rotated, changed, unchanged, added, removed}`; any other `text` throws a TypeError before anything is touched. Its counts follow `staleness` against the prior capture at `current.json`: an equal digest is unchanged, another changed, a row the prior lacks added, and a prior row with none now removed; with no readable prior capture every row is added, and `ignored` says why an existing `current.json` was not taken as one. Rotation is by authored revision, as D08 rotates: a capture at a new authored revision makes the prior `current.json` the new `previous.json`, renamed, so byte for byte; one at an unchanged authored revision (one that changes runtime-band sources alone among them) keeps `previous.json` while it holds a capture at another authored revision; with no readable prior capture, a `previous.json` at another authored revision is kept as the most recent capture there is; a `previous.json` at the new authored revision, or one that is no capture, is moved aside before `current.json` is written and removed after; and a `current.json` that already holds `text` is not rewritten. Nothing is written until every check passes: a link or junction on the way, an entry at `.ia`, `.ia/work` or `.ia/work/snapshot` that is not a directory, or an entry at either path that is not a regular file, refuses as PATH-UNSAFE; for an entry that is not a directory or not a regular file the error's optional `path` names it, and a link or junction is named in the message. The new bytes are staged first in a unique same-directory temporary file, flushed and owner-only; a rotation then moves `previous.json` aside, renames `current.json` to `previous.json` and the staged file to `current.json`, and a step that fails undoes the ones before it in reverse, so a failed write leaves the pair it found and only the error escapes (a process killed between two renames can leave the moved-aside file and `previous.json` holding what `current.json` held, which the next capture rotates again). Concurrent captures of one root are last-writer-wins. The pair is local working state under `.ia/work/`, never a source and never read by admission, and no handle writes it.

This is a bounded path/role allowance, not an asset validity verdict: the distribution owner verifies the closed manifest, exact resource pins and native joins before packing/verifying/installing guide-bearing archives. Native floor code remains supplied by the fixed language floor rather than an archive's documentation assets.

Path identity: `src/paths.ts`, exported from `@inventarch/db`, compares paths by what the volume opens, because APFS folds case and Unicode normalization and NTFS folds case. `sameFile` compares device and inode (a path it cannot examine, such as a link loop, is compared by `pathKey`); `within(parent, child)` walks the child's real ancestors by device and inode, and compares folded settled spellings only while the parent does not exist; `unaliased(path, real)` accepts another spelling of the same existing names and refuses a link or junction in any component, and a path that is not absolute and normalized, since the kernel walks a `link/..` pair through the link (on win32, where the kernel removes `..` before it follows a junction, it compares the normalized path case-folded, which also refuses subst drives and 8.3 names); `linked` finds that link; `pathKey` folds the key of a relative path that may not exist, case on win32 and `caseFold` on darwin: NFC and full Unicode case folding, as APFS compares names, so `ß` and `ss` are one name there, while the dotless `ı` stays apart from `i`. The same key names draft paths (`preview.ts`), editor overlays (`editor/index.ts`) and sources (`inputs.ts`), so on macOS two of them that differ only in case or Unicode case are one path, refused as a duplicate; a case-sensitive APFS volume holding both `A.ia` and `a.ia` is refused there as a duplicate source. `@inventarch/runtime` re-exports all of them but `linked` and `caseFold`, for the apps that depend on it rather than on `@inventarch/db`.

### Explicit package-local authored inputs

`InputOptions.authoredRoots` selects a frozen, sorted list of repository-relative package directories. Selection is explicit host input; the database does not discover a monorepo, inherit a parent workspace, or read package policy JSON. Each selected directory contributes only its `.ia/src/systems/<owner>/` native files, at authored workspace precedence and with the original physical `source.path`. Vocabulary identities are unchanged. The sole system declaration remains at the repository root; a package cannot carry its own system declaration, floor, workspace/adoption manifest, distribution lock, release manifest, or legacy package authority. Existing structural admission and duplicate diagnostics apply across the combined source set.

Directories must be portable, canonical, disjoint and unaliased. The reader refuses junctions/symlinks, hard-linked native files, nonregular sources, invalid UTF-8, missing root system context and ambiguous path spellings. Selected package capture is bounded to 1000 package roots, 20000 native files, 1 MiB per file and 64 MiB aggregate native bytes. Reads allocate at most the statted size plus one byte and refuse concurrent size/metadata changes. Hosts must additionally bound their full repository capture and verify inventory membership, package-to-record correspondence, ownership, policy/evaluator freshness and one writer.

Selection and exact source bytes participate in the input fingerprint and admitted revision. Refresh therefore invalidates previous scopes when a selected package source changes. A contextual scoped read uses the root handle; opening a package directory alone supplies no parent definitions and does not admit those instances. No package-local editor write or preview target is added: existing draft paths remain root `.ia/src` paths. This is the upstream read prerequisite, not a claim that a consuming monorepo has completed its package-record cutover or installed qualification.

Version-1 `.ia/workspace.json` additionally accepts `open` bindings at `.ia/open/<id>/<revision>` with an optional canonical workspace-relative `reach`. Discovery verifies exact native source bytes as it verifies adopted bindings, then places them at open band 50, below adopted band 90 and authored band 100. `adoptedBindings` includes these bindings with `placement: "open"`; legacy bindings retain their prior shape. The combined binding ceiling remains 16. These bindings are source data and confer no executable loader or write grant.

Distribution engine compatibility: the reader retains `IA-DB-SOURCE-UNAVAILABLE` but classifies an unsupported lock or archive range as `InstallationError.reason: engine-incompatible`, naming the required range and actual reader engine. It does not classify that mismatch as damaged bytes or modify the lock. The exact released lock marker `0.1.0` retains its existing forward-compatibility exception; archive engine ranges remain strict, including root release controls requiring 0.1.1 or later.
