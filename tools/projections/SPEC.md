# Public projection fixtures

Original synthetic native records and inert resources exercise public host projection, template rendering and distribution commands. Generated output does not establish live agent qualification.

`generate.ts` renders this repository's committed projection (decision packet-tracking-policy; milestone position-packet task replace-renderers): the position packet of its own admitted records, with the CLI's command catalog, rendered by the runtime's claude adapter for the repository target, `CLAUDE.md` and the `ia-authoring` skills under `.claude/skills/` and `.agents/skills/`, each with `<!-- Generated by ia project; edit the cited native records. -->`. No per-system steward agent is rendered. A file the 1.x renderers marked, with either 1.x marker, is owned and replaced. A marked file under `.claude/agents/` is stale: `--check` reports it and `--write` deletes it, and an unmarked one is left. A steward-guard registration this checkout owns (`.ia/distributions/hosts/claude-guard-workspace.json` and its group in `.claude/settings.local.json`) is stale too: `--check` reports `.claude/settings.local.json`, and `--write` removes the group and its state through apps/distribution's guard registration, which keeps every other byte of the settings file, before it deletes any steward file, and prints `guard retired` (plan amendment B11).

Only those three files are committed (decision packet-tracking-policy; milestone position-packet task untrack-steward-agents). `.gitignore` ignores `/.claude/agents/` and git tracks no file under it, so an agent file there, a 1.x leftover or a developer's own, stays machine-local. `generate.test.ts` pins the tracking: `CLAUDE.md` and both skills are tracked, `.claude/agents/` holds no tracked path, and the repository's tracked ignore files alone, read with no system, global or personal ignore configuration, ignore `.claude/agents/` through the `.gitignore` rule and none of the three files.

Every `generate.ts` refusal names one command to run next. A corpus with admission errors names `pnpm native:check`, which prints the findings. A steward-guard registration the generator cannot retire names `pnpm projections:generate` after its ownership state and guard group are deleted. An output set outside the renderer contract, or a path escaping the root, names this directory's tests, which pin that contract. An unmanaged file names `pnpm projections:generate` after the named file is deleted, an aliased root or path names it after the repository is opened at its real path or the link is replaced, and a usage error names it directly. Each of these is checked before any file is written. Files are then published one at a time, each path checked again as it is written, so a projection that changes on disk, or a root or path found aliased, during publication stops the run after the files already published; the changed projection names `pnpm projections:generate` again, and an alias names the repair above. A failure raised beneath the generator, such as a native source the database cannot read or a file the system will not replace, names `pnpm projections:generate` once it is repaired. `--check` names `pnpm projections:generate` when it finds drift.
