# Modular test execution tooling

Owns the task manifest, the inventory and planning commands, the report and gate schema, and the reusable execution primitives named in the modular test execution contract. These are read-only developer tools plus one runner; they schedule and report work, and they neither weaken an assertion nor establish that a cached result was computed from complete inputs.

`tasks.json` is the manifest. It declares `schemaVersion`, the timeout `profiles`, the named `inputProfiles` and every task. A task carries a stable identity of the form `<owner>:<behaviour>`, its owning project, its Vitest file selection or its command, a timeout profile, the platforms and mode it applies to, an input profile, dependencies, disjoint outputs, a cache decision, a worker limit, a resource class and the qualification leaves it takes over. Shard number, runner hostname, run identifier and commit are execution metadata and never appear here. Measured durations live in `schedule.json`, which is scheduling metadata: changing it moves a task between shards and must never change what the task is.

`nx-plugin.mjs` contributes each task as an Nx target. A task's hash is its input profile plus the files of the projects Nx's import graph says its owner depends on, excluding their test files; a root task whose entries all lie in one `tools/<dir>` is owned by a `tools-<dir>` project that also depends on the root project. The task's manifest entry and timeout profile are target options, so editing one task's entry does not invalidate other projects' results. A dependency task's hash and outputs never enter a dependent's hash.

`pnpm tests:inventory [--json] [--cases]` enumerates every Vitest project from the workspace globs plus the root tools configuration, asks Vitest itself which files each configuration selects, expands the legacy `platform:qualify` chain into the commands that actually execute, and validates the manifest against all three. It fails on: an unassigned discovered file, two tasks claiming one file on one platform, a selection Vitest does not discover, a target that selects nothing, a project with no task, a test file Git can see that no configuration selects, an unknown timeout or input profile, a worker limit above its profile's ceiling, a cacheable task with no declared outputs, an uncacheable task with no recorded reason, a skip without a named reason, overlapping outputs, an unknown or cyclic dependency, a duplicate identity, and a qualification leaf no task owns. `--cases` additionally expands parameterized cases through Vitest for pre/post migration coverage comparison; it imports the tests, so it reflects the built state of the checkout. Assignment coverage is mechanical: it does not prove an input profile is complete, which is what the mutation probes are for.

`pnpm tests:plan --platform <linux|windows|macos>` sorts the applicable tasks into build, static, test and emitted lanes and assigns the test lane to shards. The build lane holds every `:build` task and every task another task depends on; the static and test lanes wait for it, so their prerequisites restore from the remote cache instead of being repeated on each runner. Placement is longest-first into the least-loaded compatible shard with task-identity tie-breaking, so the same manifest and schedule always produce the same plan. Native-heavy tasks are placed first on their reserved shards; general work then fills the least-loaded shard of either class. Each shard still executes tasks serially, so this uses spare capacity without raising native concurrency. A task a platform has not recorded is placed by Linux's duration for it, scaled by the median of that platform's recorded durations over Linux's for the tasks both recorded (1 while they share none), so a partial record never leaves the rest on one estimate. Only Linux lends and Linux never borrows, so recording macOS or Windows never moves another platform's plan; recording Linux moves the estimates the others borrow from it. A task neither the platform nor Linux has recorded receives at least the slowest estimate the platform has, scaled ones included, and always runs; it is never dropped. `--shards` and `--native-shards` take one count for every platform or one per platform (`linux=8,windows=8,macos=2`). `--matrix` emits a GitHub Actions matrix, `--record <directory>` folds executed durations back into `schedule.json`, and restored results are excluded because a cache hit measures transfer, not execution.

`--ci-matrix --event <GitHub event> --head-sha <sha> --verified-sha <sha>` emits the workflow's `tests`, `build`, `static` and `emitted` matrices, a `gate` matrix with one row per planned platform on its `RUNNERS` label, the planned `platforms`, and `run`. Pull requests plan Linux alone (`PULL_REQUEST_PLATFORMS`); main pushes, scheduled runs, manual dispatches, every other event and no event plan Linux, Windows and macOS. The macOS Homebrew smoke runs when macOS is planned. Narrowing drops whole platforms and never moves a task within one, so a pull request's Linux rows equal a push's. `run` is `false` only for a `schedule` event whose head is the commit the last successful scheduled run verified; an empty or unknown verified commit, and every other event, gives `true`. A Windows- or macOS-only failure is caught on main after merge, not on the pull request. The planner writes these lines and then lets the process end on its own, never through `process.exit()`: off Windows a child's piped stdout is a socket that Node writes asynchronously, and macOS gives that socket an 8 KiB buffer, so exiting can drop matrix lines the reader has not taken yet.

`pnpm tests:run --task <id>` executes exactly one declared task on the current platform and writes `evidence.json` under that task's `artifacts/tests/` output. It refuses a task that does not declare this platform, applies the task's timeout profile and worker limit as explicit Vitest options, exports the profile's subprocess bound to the tests as `IA_TEST_SUBPROCESS_TIMEOUT_MS`, disables retries, and treats a missing machine-readable result or an exceeded ceiling as failure. This runner always executes; restoration is the scheduler's concern.

Orchestration supplies a fresh invocation token to its runners. Evidence retains that token when cached, so execution attribution compares invocation identities rather than wall clocks that can move backwards. The token is execution metadata, excluded from hash inputs; older evidence without a token is treated as restored and still requires its computation hash.

`pnpm tests:gate [--evidence <directory>] [--platform <name>]` compares the received evidence against the exact expected task and platform set. Missing, duplicated, failed, empty and unexpectedly skipped work fails, as does a result for a task the planner did not require, an evidence file that cannot be read, a restoration without a computation hash, and a result whose outcome and source disagree. A declared skip that was not observed also fails, because the skip list is part of the task contract. A restored report keeps its original execution provenance; that commit is reported as the writer's, never as this run's. The gate is not cacheable and is trusted only as far as the cache boundary that produced the evidence is qualified. In the workflow, each platform's gate job runs this comparison for its own platform and then also fails while any job it waits for failed or did not finish on any platform, so a failure on one platform turns every platform's gate red. It waits for every other job in the workflow, the Homebrew Node smoke included; that smoke runs only when the plan includes macOS, and its skip is accepted only then. The gate's rows are the planner's `gate` matrix, so they always equal the planned platforms. Every job after the plan, the gate included, skips when the plan emits `run=false`; the gate runs on any other value, an empty one from a failed plan included. The gate's job list is written by hand. Tools tests hold the gate's matrix to the plan's output, the gate's `needs` and refusal loop equal to the workflow's other jobs, and the planner's arguments to what the Plan job passes for each event; they read the workflow through `workflow.ts`, a line reader, because `yaml` is not a declared dependency.

The timeout profiles are `unit`, `database`, `http`, `native` and `installed` from the shared contract, plus `corpus` for this repository's large fixture-driven pure suites, whose configurations already carry a thirty-second ceiling. Their values reconcile the allowances the suites already declare; they are correctness ceilings, not performance targets, and raising one is an execution-contract change that belongs in the manifest where it invalidates cached results. `database` and `http` are declared for the shared contract and are currently unused here.

`resources.ts` owns asynchronous cleanup. A release is registered as its resource is acquired, so a scope that fails partway through setup still unwinds what it holds; disposal is idempotent, reverse-ordered and bounded per release; the scope's signal aborts before the first release runs, because racing a promise is not cancellation. A throwing release does not stop the unwind, and every failure is reported. When the body itself failed, the body's error is what propagates and the teardown diagnostics travel with it on a non-enumerable `teardownFailures`; a bounded release that never settles is recorded as abandoned rather than claimed as cancelled.

`subprocess.ts` runs children under an explicit ceiling. A child runs in its own process group on POSIX and is torn down with `taskkill /t /f` on Windows; both reach descendants only as far as the host exposes process ancestry, and the regression case asserts descendant termination only where it can first observe the descendant, rather than passing on an unobservable claim. Output is truncated at a declared bound rather than buffered without limit, an aborting signal terminates the tree, and a run with no positive timeout is refused. `spawnOwned`, for a child whose output a test reads while it runs, takes the same required deadline and ends the process tree on its own clock, so a test blocked on a read that never settles cannot keep the child alive past it: the ended child closes its pipes and the read settles. The scope's disposal clears the deadline and reaps the child as well. Export keeps `spawn-ratchet.test.ts` and `direct-spawn-baseline.json` private, because the ratchet scans private apps and packages, and `tools/release` refuses an export whose tools tests have no task in the exported manifest.

The task runner (`run.ts`) imports the [temporary-directory selector](../temp/SPEC.md) before anything else, so every task and its children run with a physical `TMPDIR`.

Regression tests must exercise unassigned, duplicated, undiscovered, empty and orphaned test files; unknown profiles and worker limits above their ceiling; overlapping outputs and cyclic dependencies; unowned and nonexistent qualification leaves; script-chain expansion and unsupported workspace globs; failed, empty, unexpectedly skipped, mislabelled and unhashed evidence; deterministic and rebalanced placement; prerequisites placed in the build lane; platform selection by event and the scheduled-run skip; conservative estimates for unknown tasks; restored results excluded from timing; reverse-order and partial unwinding, throwing and hung releases, preserved primary errors, and hung and descendant process termination. Root build runs `docs:audit` over this contract; the tools suite and `tsc -p tsconfig.tools.json` cover the implementation.

Exit 0 means the mechanical check passed, exit 1 means findings or an operational failure, and unsupported flags exit 2. No command here certifies semantic test quality, product acceptance, or that a remote cache boundary is trustworthy.

## Clean-shard prerequisites and diagnostics

Timeout profiles declare an independent `taskTimeoutMs` watchdog; a task may override it explicitly. Both are finite (the runner caps accepted budgets at ninety minutes). Test-file counts do not determine elapsed suite time: one file can contain many serial tests with explicit longer bounds. Per-case and hook deadlines remain separate. Inventory validates the task budget and the runner refuses invalid values.

Remote reuse requires `--remote`, a server URL and an access token. CI supplies the opt-in and writer credential on main pushes and trusted same-repository pull requests; fork pull requests and forced-full runs remain uncached remotely. The runner logs why remote reuse is disabled. The enxtur server currently offers a single read/write token, so separate reader access and repository isolation require an additional server/proxy configuration; setting another GitHub secret alone does not create those capabilities.

Every package build declares its direct workspace package builds as prerequisites; inventory rejects an omitted edge. Tools that qualify built hosts or native bundles declare the build closure explicitly. A successful run in a previously built developer checkout is not evidence of clean-shard correctness. Qualification must also run in an independent checkout with no `dist` or task-cache outputs.

The runner retains `output.log` and the original `vitest.json` alongside normalized evidence, and streams test output while it runs. Orchestration streams both attempts, including the original cache diagnostic before a transport fallback. Generic test timeouts, connection refusals and authentication failures do not trigger a cache fallback without cache-specific diagnostics. Orchestration exports those diagnostics for requested tasks. The normalized case list is not a replacement for assertion messages and stack traces.

Cache mutation probes use a disposable checkout and an independent Nx cache. The dependency-free language probes share installed tools read-only; the marketplace restoration probe installs its own dependencies using the source checkout's explicit pnpm store path, preferring cached packages but permitting a missing package to be fetched under the frozen lockfile. This avoids choosing an empty store on a different Windows drive; install failures retain pnpm stdout and stderr. Source/configuration mutations never touch the caller's tracked files. Probes restore the original cache epoch, including a nonempty CI epoch. The subprocess regression observes a live descendant heartbeat, includes a deliberate pre-abort delay, and asserts that the heartbeat stops after awaited termination. Earlier writes do not count as survival; an independent watchdog and owned cleanup bound a failing probe.

## Cache restoration and public scheduling

Public extraction uses the reviewed release task policy rather than this private manifest unchanged. Public hash inputs include formatter configuration, license/notice files, neutral examples and CLI/distribution assets. Mutation probes verify invalidation and restoration in an isolated cache, with inherited Nx bypass flags removed only from the probe environment and restored afterward. The public workflow has no hosted-cache credential requirement and persists both Nx cached outputs and their SQLite index. Public scheduling estimates are recorded from successful executed public tasks and retained in the extraction schedule template; restored results are excluded. Measurements alone do not establish final qualification. See the M3 handoff for the independent public/private gates still outstanding.

The marketplace build owns `apps/marketplace/dist`, `apps/marketplace/native/foundation` and `apps/marketplace/native/manifest.json`. Its inputs include the authoring-resource manifest and root license as well as the native sources. The native bundle is generated, Git-ignored build output; declaring only `dist` produces a cache hit that cannot run installed qualification or foundation-backed tests. A disposable-checkout regression removes only the generated foundation directory and manifest after a cold build (the authored `native/.ia` input stays intact) and requires a cache restoration to recreate its manifest and foundation.

The public workflow plans four test shards on Linux and Windows and two on macOS, with no reserved native shards. Pull requests select Linux; pushes, scheduled runs and manual dispatches select all three platforms. Explicit local `--platform` plans remain available for each platform. The planner uses recorded task durations as scheduling estimates; update them with successful task durations through `tests:plan --record`.

An already-aborted `runBounded` signal rejects with its original cancellation reason before spawn. This is a dispatch refusal, not a fabricated child result. Aborts after dispatch continue to terminate the owned tree and report its observed `BoundedResult`; positive timeout validation still precedes dispatch.

Cache-probe setup clones HEAD through the Git transport into independent packed objects (no hardlinks or alternates), then overlays only changed tracked and nonignored untracked files (including tracked deletions) from the working checkout. This preserves uncommitted source inputs while avoiding a second full-tree copy inside the unchanged setup deadline. The existing mutation/restoration cases remain the behavioral gate; their timeouts and case identities are unchanged.

Scheduling observations can be exported with `pnpm tests:plan --record <evidence-directory> --record-out <output-file>`. The output is a complete candidate schedule; this option leaves the checked-in schedule unchanged. CI gates attempt to upload `schedule-<platform>` artifacts alongside their evidence on success or failure; timing export and upload are best effort and do not determine the required gate result. Import only the matching platform observations when refreshing estimates; new task identities keep conservative estimates until measured. An exported schedule is planning data, not qualification evidence.

CLI tests have independent task identities for units, initialization, registry, workspace behavior, installed journeys and four host suites (registration, recovery, doctor and install). The unit group has no build prerequisite. Host cases keep isolated mutable roots and IA homes; only immutable archive preparation is shared within a process. Selected CLI test inputs retain production source, non-test helpers and resource trees while excluding sibling test implementations, so editing one suite preserves other suite hashes.

Input mutation and restoration in the disposable cache probe use distinct whole-second modification timestamps. Nx 23.2.1 persists file hashes by that timestamp on Linux/macOS; two writes inside one second can otherwise retain the changed hash after restoration. This does not clear or bypass the task cache, change selected input definitions, add sleeps, or claim an upstream metadata-cache repair. CLI probes assert return to the baseline after each restoration as well as the final complete sequence. A deterministic equal-timestamp reproduction matches the Linux sibling-suite failure; normal source/package qualification remains separate.

## Native corpus cache closure

A test that discovers authored records through the filesystem hashes the entire workspace record tree, even when no TypeScript import names those files. Graph, compliance, vscode, db, runtime and authoring-system tests use `workspace-records`. Language conformance tests also read the compliance language fixtures, so `language-conformance` includes that external fixture tree. System-local case readers whose inputs are already inside their own project keep `owner-source`. Pure builds do not acquire the native test corpus merely because their tests read it.

The real Nx hasher regression changes an existing native record, adds a native record, restores both inputs and changes an external language fixture. It checks every affected task and a build control. Cache epoch 2 invalidates prior results whose native inputs were incomplete. Scheduling observations are best effort: export and upload run after a failed gate when the job still has evidence, but cannot change qualification success or excuse a failed gate. Unknown task timings retain conservative estimates until measured.

The shared Biome input follows the workspace's active configuration: source uses `biome.jsonc`, while the public exporter emits and hashes `biome.json`. Public Nx projection also removes only the private marketplace native bundle and service-tool globs; authored public records, required resources, selected-test profiles and runtime/environment inputs remain. The real cache probe changes a boolean setting in the active configuration and requires execution followed by restoration. This checks the shared package-task input boundary; the root lint task already hashes the configuration through repository inventory.
