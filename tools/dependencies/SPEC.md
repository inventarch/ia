# Package dependency check

PT5 adds `@inventarch/authoring-system` with public db/language/runtime dependencies. Composition imports that owner for scoped engine draft tools. Distribution has an explicit additional host dependency on authoring-system for identical contextual formatting; no foundation package imports this upper owner. Source-relative Stage E wrappers remain repository tooling and delegate to the public package.

Distribution PT2b exception: `@inventarch/distribution` may import public language, graph, db and composition APIs, alongside its authoring dependency. Graph supplies the shared canonical digest codec (`canonical`, `digest`, `copy`, `CodecError`) used by release assessment; the session package re-exports `CodecError` and wraps the functions so they refuse with its `SessionError` subclass, and no longer needs to be imported for the codec. Distribution owns host publication and explicit-root consumer commands; foundation packages cannot import the distribution app. Its package manifest declares every such installed dependency. This exception does not broaden other hosts.

PT4 adds the pure `@inventarch/template-system` owner with public language/runtime dependencies. Composition may import template-system for scoped captured rendering; template-system cannot import composition or the distribution app. The installed composition manifest declares that dependency, so both development and emitted consumers load the same owner implementation.

Owns enforcement of systems design §1.1 and graph plan Task 4. Runtime source under packages/*/src, apps/*/src and .ia/src/systems/*/src is parsed as TypeScript to inspect import/export declarations, inline import types, import-equals, require calls and dynamic imports. Internal dependencies in package manifests and source must follow the explicit allowed package map. An allowed cross-package `@inventarch/*` source import must also be declared in dependencies, optionalDependencies or peerDependencies; a hoisted development dependency cannot qualify an installed package. Relative imports may not cross a package boundary, even to a permitted dependency; use its public package name. Unknown @inventarch packages and nonliteral runtime module loads fail closed. Test/build tools outside runtime src are composition roots and are not constrained by this runtime map.

The current map admits language→none, graph→language, compliance→language+graph, db→language+graph+compliance, runtime→language+graph+db, and read/editor/hook apps→runtime. The generic `@inventarch/workspace-runtime` row admits language, graph, db, runtime, compliance, agent-system, session-system, template-system and authoring-system, and composition may import it; it never imports composition. Since the runtime split, the `@inventarch/distribution` and `@inventarch/steward-hook` host rows admit workspace-runtime in place of composition: both consume only the generic runtime (capture, resources, projections, templates, lifecycle and authoring), so neither declares `@inventarch/agent-composition-system`, and distribution's tests reach the composition compiler through the root development dependency. The native session package imports only graph, for the canonical codec; agent may import session/runtime/language/graph/db; composition may import agent/session/runtime/db/language/graph/compliance. The agent-runner app may import runtime/agent/session/composition. Folio may import only language: it is a vocabulary-join host, not a Door host. The exact allowlist is in [check.ts](check.ts). Add a new system package only with its owning spec's dependency decision. The checker reads files and reports errors without changing them. It does not prove arbitrary program behavior or police dynamic code evaluation. Tests exercise every supported import form, manifests and cross-package escapes. Root test/build run the repository check; typecheck includes its implementation and tests.

Service contracts may import only their own modules and Zod. Service host may import service-contracts; marketplace may import db, composition, service-contracts and service-host. Foundation/execution packages cannot import service transports. InventArch may import composition, db, graph and runtime. The explicit `@inventarch/cli` host entry permits runtime, InventArch, workspace-runtime and db; foundation runtime gains no reverse dependency. Since the runtime split the CLI row names `@inventarch/workspace-runtime` in place of composition (its one composition import, the Codex lifecycle profile, lives there) and the MCP door row drops composition, which its sources never imported. TypeScript/build and isolated package consumers separately verify actual public export resolution.

Nonliteral module loads are refused in every runtime source, including development producer paths. A literal import of `@inventarch/monorepo-kit-host` or its `/development` capability is permitted only for a CLI host with that package declared as an installed dependency. Other owners and private subpaths remain refused. Synthetic fixtures exercise these restrictions without depending on a private producer implementation.
