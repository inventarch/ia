# kernel tooling contract

## Purpose

Maintain the generated language kernel and verify drift against the selected floor.

## Modules

- [generate.test.ts](generate.test.ts) — behavior and refusal coverage.
- [generate.ts](generate.ts).

## Commands

- `pnpm kernel:check`: `node --conditions=development --import tsx tools/kernel/generate.ts --check`.
- `pnpm kernel:generate`: `node --conditions=development --import tsx tools/kernel/generate.ts --write`.

Commands report success as exit 0 and evaluated failure as exit 1. Corrected strict parsers use exit 2 for usage errors. Existing command-specific defaults, flags and refusal behavior are described below; a check never implies a write.

## Inputs

Canonical floor source and kernel generator implementation.

## Outputs

--check compares generated bytes without writing; --write updates the declared generated kernel files.

## Prerequisites

Source-aware Node/tsx with development conditions; the entry path remains stable because shipped bytes cite it.

## Validation

Task ownership: `tools:test-kernel`, `kernel:check`. `tools/testing/tasks.json` declares platform, timeout, prerequisite, output and input-profile contracts; `nx.json` defines their actual file/runtime inputs. Live discovery and mutation tests validate coverage and caching.

## Invariants

The evaluated floor and kernel evidence must describe the same source revision. Generated bytes are deterministic.

## Limits

A generated-kernel check alone is not a full compliance or release gate.
