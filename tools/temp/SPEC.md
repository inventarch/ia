# Temporary-directory selector

`physical-temp.mjs` sets `TMPDIR` to the canonical path of the selected temporary directory whenever the two differ. Usually that is a link in the path: macOS reaches `/var/folders` through `/var`, and its `/tmp` fallback through `/tmp`, a link to `/private/tmp`. A non-canonical spelling of a real directory is rewritten too. Every Vitest configuration and the task runner (`tools/testing/run.ts`) import it before anything else. So does each entry point under `tools/` that creates temporary roots under `tmpdir()`, except `tools/distribution/qualify-linux.mjs`, which runs only inside WSL Linux, and so do the plain-node scripts beside `apps/vscode`'s tests. `physical-temp.test.ts` parses those files and checks three things: the first import of every Vitest configuration a task runs; the first import of every script that makes a temporary root, recognized by its `tmpdir()` and `mkdtemp` calls (a root made with `mkdirSync` is not recognized); and, for the listed modules that are not entry points, that every script loading one is named with it and is listed too or imports the selector first. Their fixtures then sit under a path the toolchain's alias refusal accepts, and children inherit the variable. It relaxes no alias refusal. It changes nothing on Windows, where `TEMP` and `TMP` select the directory and `canonical-temp.mjs` covers the runners, and it leaves an unreadable `TMPDIR` for the operation that uses it to report.

The selector is its own Nx project, `tools-temp`, through the `tools:test-temp` task that owns `physical-temp.test.ts`, and it imports only Node built-ins. A project that imports it therefore hashes this project's two files, the selector and this SPEC, and the two packages its test imports, `vitest` and `typescript`, which every other task hashes already; not the testing tools, their task manifest or their dependencies, as it would if the file lived in `tools/testing`. `nx.json` also lists it in `sharedGlobals`, beside the runner's own files, because the runner imports it for every task. Keep that entry although the file has an owning project: the graph reaches it only from projects that import it, and a task in any other project still runs it through the runner.
