# Installed SDK qualification

Verifies receipt-selected public archive bytes, dependency closure and independently installed ordinary Node consumers. Executes deterministic onboarding, first-party captured read and explicit specification-body fixtures. No private checkout, paid provider or publication is part of this gate.

The explicit pnpm launcher argument accepts either a JavaScript entry or a native executable through `tools/entry/package-manager.mjs`; a pnpm 12 binary is never parsed by Node. The caller supplies the qualified package-manager version and populated store. An offline install remains a separate observation from any earlier store population.

The candidate is verified against its committed v2 public input seal and the retained `npm-release.json` with its exact archive integrities and compatibility companion. SDK membership combines the core runtime packages with systems from the public language manifest. No extraction receipt in Git metadata is read. Run this only against a fully prepared local release candidate; it does not query or publish to a registry.

Each selected archive is opened without following a link, judged a regular file by its open descriptor and read once through it; the digest check, the packed `package.json` that `tar` reads from stdin and the recorded pin all come from that one read. pnpm still installs each archive from its path.

That read binds the digest check, `tar` and the pin, not the install. A known limitation predates it: the release check (`verifyRelease`) and the expected digest each read a selected archive by its name before that read, and a FIFO already at that name blocks the earlier read; after the check, pnpm installs each archive by reopening it from its path. An archive replaced after its check is therefore installed though its pin records the checked bytes: the installed bytes are not bound to the checked buffer.

`qualify-sdk.test.ts` runs the script without network access against archives it builds in a temporary directory, with `qualify-sdk-fixture.mjs` preloaded to stub the release, receipt and language-manifest readers, record each buffer handed to `tar` and change one archive just before its open, during its read or when its bytes are handed to `tar`. It requires each pin to equal both the archive's bytes and the buffer `tar` was handed, admits a hard-linked archive, and refuses an archive that grows, shrinks or is rewritten while it is read, is replaced between its selection and its open, or holds a packed name or SDK closure other than its selection. It also shows the limitation above: an archive changed after its check keeps its pin while the install reads the change. On Linux and macOS only, it refuses a symbolic link at selection or put in place later, the same bytes under a new identity once open, and a FIFO put in place after selection, without waiting for a writer. The `tools:test-runtime` task owns these tests.
