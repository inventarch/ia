# Installed system package verification

Use the installed @inventarch/distribution/system-package entry point. verifySystemPackage(root, expectedBindingDigest, { archives }) verifies regular package files against an externally selected binding digest and exact native archive map. It never imports code, discovers handlers, grants authority or installs systems.

Binding format 2 gives each of eleven public systems exactly one native archive. Five packages retain their compiled APIs at explicitly selected npm 1.1.0. Six native-only npm identities begin at independently selected 1.0.0: compliance, governance, hook-authoring, learning, work and workspace systems. Native archives are individually selected at 1.1.0; IA syntax 1.0 and distribution format 1 are unchanged. Native-only exports address archive/binding data and have no executable entry point.

Each binding pins its local native archive, native manifest, owner, exact final package.json bytes (including all execution and dependency metadata), compiled files when present, the complete owned packaged file inventory and dist/native-selection.json. Only package.json and the three separately verified binding/native/selection files are outside the payload list; no root file, nested code or dependency directory is silently ignored. Regular store hardlinks preserve byte verification; symbolic links and junctions refuse. Caller-supplied archives must match that exact selected lock. Missing, substituted, duplicate-owner or version-skewed selections refuse. The unreleased format 2 now requires complete manifest and payload pins. Earlier local format-2 bindings without them refuse and remain historical evidence with their matching verifier; they are not migrated or relabeled. Legacy format 1 retains its original standalone verification contract, which does not establish complete package-root integrity.

All public guide descriptors and reference documents remain with authoring-system, which also owns the two shared floor teaching documents. The immutable native floor comes from the installed language; it is not repackaged. Other systems own their native sources and teaching. Distribution declarations remain under workspace-system and root their respective system.

Existing native declarations and teaching currently require the full eleven-system dependency closure. Separate artifact ownership does not imply a minimal standalone installation. Atomic selected-set packing admits existing cyclic package dependencies together while native system dependency rules remain unchanged. Standalone and incremental packing still refuse an external native declaration. Integrity does not establish authorized writers, arbitrary plugin execution, OS enforcement or complete release readiness.

The producer resolves the supported publishConfig exports override and receipt-pinned default catalog, then preserves the pinned pnpm script-field order before hashing the final manifest and uses an exact positive package.files list plus npm-included root README/license documents. Unreviewed globs, ignore controls, bundled dependencies, packing lifecycle scripts and unsupported publishConfig transformations refuse. It verifies a separate complete package view; the workspace source tree is not an installed package. Qualification must also verify actual packed and installed membership and manifest bytes. Native-only packages permit the five reviewed root teaching/license documents and separately verified native data; executable metadata (including bin, scripts, main, imports and optional/peer dependencies) and other payload files refuse even under a newly selected binding. Integrity never executes the package or authorizes its code.
