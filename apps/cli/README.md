# @inventarch/cli

The IA 2.0.0 command-line interface creates workspaces, validates, inspects, reads and captures native records, shows the position body for a scope key and a plan's delivery view, projects the position packet for an IDE host, and manages native distributions and host registrations. It requires Node.js 22.22.0 or later within Node 22.

Install the [published package](https://www.npmjs.com/package/@inventarch/cli) globally with `npm install --global @inventarch/cli@2.0.0` to use `ia` across projects. For a project-local installation, run `npm install --save-dev --save-exact @inventarch/cli@2.0.0` in your JavaScript or TypeScript repository and use `npx ia` in place of `ia`. Either way, each initialized project keeps its own records in `.ia/`.

The [main quick start](https://github.com/inventarch/ia#-quick-start) walks through initialization, a first record, validation and VS Code setup. To run from a source checkout, run `pnpm install --frozen-lockfile` and `pnpm build`, then use `node /path/to/ia/apps/cli/dist/main.js` in place of `ia`.

```sh
ia --version
ia init demo --host none
ia init demo --host none --apply --yes
ia validate --root demo
ia capture --root demo
ia inspect --root demo
ia read agent-system/binding/agent/public-agent-system-steward --root demo
ia project claude --root demo
ia vocabulary plan --schema
```

`init` previews changes unless `--apply` is supplied. Its language base, `inventarch/language` 1.2.0, is bundled with the CLI, so creating a workspace needs no registry connection. It authors three records in `.ia/src/workspace.ia`: the `@workspace demo` record, which composes the eleven public systems and declares `.ia/src` as its authored source, the participant `@agent demo`, the IDE agent working in it, and that agent's `@mandate demo-mandate`. Place authored `.ia` files beside it anywhere under `.ia/src/` except `.ia/src/floor/`, which would replace the embedded language floor, and `.ia/src/systems/`, where every folder must be a system folder with its own `system.ia`; a record's word decides which system owns it. `init` also writes `.ia/.gitignore` (ignoring `work/` and `distributions/`) unless one exists, then captures the workspace, and with `--host` writes that host's projection. `--system` adds a local `@system demo`, its steward and a `@distribution` in `.ia/src/systems/demo/` for a repository that will release vocabulary, and the `@workspace` composes that system too; without it the workspace releases nothing, and `ia pack` refuses. `ia init --migrate` previews, and with `--apply` makes, the move of a workspace an IA 1.0 or 1.1 `ia init` created to this shape: where the workspace has a 1.x language base, whose schemas lack fields the three records use, it first installs the bundled one in its place, then its own record files leave `.ia/src/systems/demo/records/` for `.ia/src/`, keeping their identities, the three records replace the 1.1.0 `@workspace` and `@distribution`, and the local system goes unless `--system` keeps it. It then captures the workspace and re-projects each registered host, which retires the 1.1.0 steward guard and deletes the steward agent files. A workspace of any other shape is refused before anything is written, and so is one with a file in the way or one that already holds an `@agent demo` or `@mandate demo-mandate` of its own, which would tie with the new records.

`ia capture` writes the admitted snapshot, with each record's digest and capture membership, to `.ia/work/snapshot/current.json` and keeps the most recent capture at another revision as `previous.json`; it reports how many records changed since the prior capture. `ia capture --preview` reports the same counts and names the changed, new and removed identities without writing anything, so the previous snapshot is not rotated away. It refuses, writing nothing, a directory whose `.ia/src` declares no `@workspace` and a floor, installed or adopted source that fails to parse; any other finding is written into the snapshot. `ia compile` is a deprecated alias of `ia capture`, removed in 3.0: it runs the capture, `--preview` and `--json` included, and prints one deprecation line on stderr. It no longer writes the 1.x `ia.compiled.v1` artifact. `--force` changes nothing, because the capture always writes, and `--out` and `--stdout` are refused (exit 2) with the `ia capture` command to run instead.

`ia read <locator>` prints the body behind a locator with its SHA-256 and the line `body not certified by this read`: the text of one cell (`<identity>#<phase>/<Primitive>`) or one requirement (`<identity>#<REQ-ID>`); else the document a record's source locator names (`work.source` on a `@spec`, `@plan`, `@milestone`, `@task` or `@decision`, `reference.document`, `template.resource`), only the section under its heading when the locator carries a markdown anchor, and for an adopted record from the directory `.ia/workspace.json` binds its mount to; else the record's own `meaning.says`. `<path>:<line>` reads the record whose source spans that line. It writes nothing, and `ia inspect` keeps the record's structure.

`ia position [--seat <id|path>] [--shape <H>] [--phase <P>] [--depth <d>] [--budget <n>] [--word <w>]` prints the position body for a scope key: with no flag K0, the repository's workspace with its pointers and tallies only; otherwise the seat and the records loaded within the budget, the pointers past it (48 listed, the rest tallied), the rules and playbooks that apply by word with their playbook cells, the blocking rules reserved outside the budget, the mandates, the frontier and the unknowns. It prints the key used and the capture's freshness first, and the two widening keys last as `ia position` commands. `--word` restricts what loads, the pointers, their tallies and the frontier to one word, and never the reserved rules, the rules and playbooks that apply by word with their tallies and cells, or the mandates, so a word hides no blocking rule. With `--json` it prints `{version: 1, ok: true, body, digest, hostNote}`, what the runtime Door's `position` operation returns. A shape, phase, depth or budget outside its closed set or cap names the same call with the set or the cap in its place. It needs no capture and writes nothing, and `ia scope` stays the machine route.

`ia next [--seat <plan|milestone|task>]` prints one plan's delivery view, computed per read and never stored: the plan `--seat` belongs to, or without it the only `@plan` the workspace authors; its milestones; its tasks in prerequisite order, each with its verdict (`exit evidence recorded (…)`, `no declared blocker` or `blocked (…)`), a basis line per requirement, its `work.status` marked self-declared, which is never the verdict's basis, and five state lines; the review items; and the command for the next task with no declared blocker. Exit evidence is a success `@observation` on the task at its current digest. With `--json` it prints `{version: 1, ok: true, view}`, the view the runtime Door's `next` operation returns. A workspace `ia init` creates authors no plan, so there `ia next` names `ia preview plan`, which shows what a `@plan` holds and where it goes. It writes nothing.

`ia project <claude|codex>` plans the workspace's position packet for one host and writes nothing: the packet's entry count and digest, each file it would create, update, leave unchanged or delete (a marked agent file a 1.x `ia host` wrote), every other `.claude/agents` file, which it leaves in place, and whether it first retires the steward guard an earlier release registered. `--apply` writes the files, `.claude/rules/ia-workspace.md` and the `ia-authoring` skill for Claude or `AGENTS.md` and its skill for Codex, and the receipt `.ia/distributions/hosts/<host>-receipt.json`, which `ia doctor` compares with the files and with a fresh render, so an edit to a record shows as an outdated projection. A file it did not write at one of those paths is named in the plan and refused by `--apply`. It registers no MCP server; `ia host` registers one and writes the same projection.

`ia preview` shows what one edit of the workspace's own records would compile to, and writes nothing. `ia preview <word> <name> [<field>=<value>...] [--at <path>]` drafts a new record into `--at` or `<first authored root>/<word>.ia`; `ia preview --relate <owned> <spelling> <target>` adds one relationship row and `ia preview --set <owned> <section.key>=<value>` (or `+=` for one list item) sets one field of a record the workspace owns: authored (band 100) and in a file under an authored root its `@workspace` declares inside `.ia/src`, named by identity or `@word name`. It prints the record before and after, the findings the edit adds, the candidate revision and the target file's current SHA-256, and refuses an unknown field, a value of another type or one carrying syntax, a relationship no consent row admits, and a record it does not own. `ia preview <word>` prints the word's lowering, schema, default file and consent. The edit is spliced into the file as it is, so other lines keep their bytes and line endings; another spelling of an existing path (a case variant, an 8.3 short name) is refused, naming the volume's spelling.

`ia author` writes ordinary records using the same arguments as `ia preview` plus `--digest <sha256>`, the file digest the preview printed. It writes only when the file is still that one and the candidate is clean, puts one `# authored-by @agent <participant> under @mandate <name> at <authored revision>` comment above the record, and moves no other record's digest. Administrative words (`workspace`, `agent`, `mandate`, `system`, `schema`, `agent-profile` and `hook`) refuse for every actor; an owner makes those changes in source and validates them. This includes the system starter. Previews remain read-only; see the [administrative source boundary](SPEC.md#administrative-source-boundary).

`ia doctor` warns when restrictive authored mandates have no supported hook declaration selecting all `.ia/src` sources for every edit tool. It never widens a hook's paths. A declaration is separate from host registration and enforcement, and the file edit guard checks Synthesis rather than word exclusions or execution limits on file bytes.

`ia read`, `ia next`, `ia validate`, `ia preview`, `ia author`, `ia capture`, `ia project` and a workspace `ia host <host> --apply` are judged by the acting participant's mandates first (Observation, Verification, Synthesis or Execution); `ia position` never is, so the position a refusal names always runs. Each takes `--actor <agent>`, a local declaration that names one of the workspace's authored participants, or its authored steward, whether the workspace leaves the choice open or names a steward; the named participant's own mandates then apply. Mandates are cooperative restrictions and `--actor` is not authentication: a mandate that should hold against its own participant also excludes the `workspace`, `agent` and `mandate` words, which holds it against that participant acting as itself, and every participant the actor can name with `--actor` needs the same exclusions on its own mandates, since naming a looser one lifts them for that invocation.

Use `ia --help` or `ia <command> --help` for the complete command syntax. `--json` returns structured output; applying a plan noninteractively requires `--yes`. Every consumer command refusal names the one command to run next, in `next` with `--json` and on the `→` line otherwise; the nine machine operations keep their one-line JSON. A recovery names `ia recover installation|host|guard|lifecycle --root <directory>`, which runs `@inventarch/distribution`'s recovery, so a global install of `@inventarch/cli` needs no `ia-distribution` binary on `PATH`. `ia doctor` reports observed state and suggested repairs. Host registration is explicit through `ia host claude`, `ia host codex` or `ia host cursor` and their `--apply` option. The projection it writes is the workspace's position packet (`.claude/rules/ia-workspace.md` or `AGENTS.md`, beside the `ia-authoring` skill), with a receipt in `.ia/distributions/hosts/<host>-receipt.json` that `ia doctor` checks; no per-system steward agent is written. `ia host` no longer registers the steward guard, and applying a projection, the refresh after `ia install`, `ia update` or `ia remove` included, retires one an earlier release registered and deletes the steward files it projected (each plan says so first), so edits under `.ia/src/systems/` are not blocked until a later release re-keys the guard to `@mandate` scope.
