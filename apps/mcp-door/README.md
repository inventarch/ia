# @inventarch/mcp-door

See [the package contract](SPEC.md) and the exported TypeScript declarations.

`ia-mcp-door [--root <workspace>]` serves read-only MCP 2025-11-25 tools over one workspace root, as UTF-8 JSON-RPC lines on stdin and stdout. `tools/list` projects `MACHINE_PROTOCOL` from `@inventarch/runtime`: one tool per Door operation whose row names one, with the row's parameter schema as its `inputSchema` (`ia_context` adds the transport-only `format`), plus `ia_vocabulary`, which reads the catalogue shipped with the server and no workspace. That is twelve tools: `ia_scope`, `ia_context`, `ia_select`, `ia_get`, `ia_records`, `ia_resolve`, `ia_search` and `ia_traverse` from protocol version 1, `ia_read`, `ia_next` and `ia_position` from version 2, and `ia_vocabulary`. `report` is CLI-only. A scope token lives as long as the server process, so a token `ia_scope` issues narrows later calls.

`ia_read` returns the body behind one locator (`<identity>`, `<identity>#<phase>/<Primitive>`, `<identity>#<REQ-ID>` or `<path>:<line>`) inside the scope, with the SHA-256 of its UTF-8 bytes and `certified: false`: a fragment's text, else the document the record's source locator names, read from the workspace or, for an adopted mount, from the directory `.ia/workspace.json` binds it to, else the record's own body. A locator that no admitted record in the scope answers is refused as `IA-RUNTIME-READ-UNADMITTED`: through a token narrower than the whole workspace, one `ia_scope` issued with `identities`, a `phase` or a `root` below the workspace root, or from such a token, without naming what lies outside the scope; through the server's initial scope, the whole workspace, or a token `ia_scope` issued from it without narrowing it, naming what its sources hold there, a record admission refused with its `reason`. A document the server cannot read is named by its workspace-relative path, never by the server's root. Pass `includeRuntime: true` to read a record at runtime placement.

`ia_next` returns one plan's delivery view inside the scope, computed per call and never stored: the plan a `seat` (a `@plan`, `@milestone` or `@task` identity) belongs to, or without one the only `@plan` authored at band 100; its milestones and tasks in one prerequisites-first order, each task with a basis line per requirement, one verdict (`exit evidence recorded (…)`, `no declared blocker` or `blocked (…)`), its `work.status` as self-declared and five state lines; review items; and `next`, the command for the first task with no declared blocker. A refusal (`IA-RUNTIME-NEXT-SEAT`, `-NO-PLAN`, `-AMBIGUOUS` or `-CYCLE`) carries `next`, the one command to run, and the `plans` or the `cycle` it names.

`ia_position` returns body(K) for a scope key inside the scope, `{body, digest, hostNote}`: the key's parts `seat` (an identity, or `{path}` for a location), `shape`, `phase`, `depth` (0 to 2), `budget` (0 to 64) and `word`, all optional, no part being K0, the repository's `@workspace` at context, orient, depth 0 and budget 0. The body is a pure function of the key and the records the scope admits, so it names no root, token or time and reads no request text, and its `digest` is the SHA-256 of its canonical JSON; `hostNote` is host state beside it, the revision and how fresh the last `ia capture` is. A refusal of the key (`IA-RUNTIME-REQUEST-INVALID`) carries `next`, the one command to run.
