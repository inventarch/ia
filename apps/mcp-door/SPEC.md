# @inventarch/mcp-door

Knowledge membership budgets apply after intersecting the original Door membership with the optional persisted `.ia/knowledge.json` selection, using the KB library's shared eligibility predicate. Excluded authored records, floor records and excluded body resources do not widen the selected view. The adapter validates the selector before budgeting and passes it to capture, retaining the Door revision check before body reads.

Public language mechanism. The [language reference](LANGUAGE.md) defines vocabulary and evaluation limits. Package exports describe the installed API. Curated agent methods and hosted services are supplied independently.

Knowledge integration adds five tools: `ia_kb_check`, `ia_kb_search`, `ia_kb_read`, `ia_kb_resolve`, `ia_kb_traverse`. They use the public KB protocol DTOs. The original Door validates any scope token, supplies membership, and must agree with the KB native graph revision before bodies are read. Unknown/stale tokens, budget overflow and graph changes refuse without widening scope. Arguments cannot change root or select export paths. Local checks expose selected-record admission and closure; workspace compliance is explicitly not evaluated, and excluded records do not contribute diagnostics. The complete JSON-RPC KB tool-result envelope, including text plus structured content and request id, is bounded to 48 KiB. An oversized result returns a bounded refusal. If the request id itself prevents even that refusal from fitting, the server rejects the request before executing a KB operation with JSON-RPC error -32600 and echoes the original id. That protocol error can exceed 48 KiB; truncating or replacing the id would prevent the caller from matching its request. Existing twelve tools and protocol negotiation are preserved.

Method tools: `ia_session`, `ia_catalogue` and `ia_method` follow the kit foundation's door contract (C1). They take structured input only; `subject` reaches no position and is kept only as `sha256:<hex>`, the value the packet's `scope.subject` and the pin's `intent.subject` carry. Each takes an optional absolute `root`, which must be the launch root or a row of `<IA home>/workspace-locations.json` (any of its three formats, runtime `readRegistry`), and refuses `IA-CORE-ROOT-UNREGISTERED` otherwise; a root holding `.ia/src` must open and its governing mandates must admit the read mode for the default actor (runtime `checkRoot`). Kits are the bundled folder (`--kits`, else `IA_KITS_DIR`), then `<IA home>/kits/<folder>/<version>/` unless `IA_CORE_NO_HOME_KITS=1`. `ia_method` is runtime `resolveMethod`: the packet `resolve.mjs` prints, field for field and with the same digest, for the same consumer, bindings, kit bytes, carrier and task, with `envelope.host` `mcp-door` and `envelope.cliSource` `in-process`. A `task` pins under `<IA home>/work-v1/<projectOf(root)>/<task>/`: the plugin's `lib/pin.mjs` takes its project from the caller and derives none, and the lanes pass a task only, so the project is the workspace folder's name as a slug (runtime `projectOf`). When the bundled folder is a plugin's `config/kits`, that plugin's `scripts/` and support files are the carrier its implementation digest and retained bytes cover, so a pin written by either reader verifies in the other. A kit's read root is restored in process from the language base this package carries in `assets/base/` (generated with the CLI's); a kit locked on another base refuses `IA-CORE-CLI-UNSUPPORTED`. `tests/method.test.ts` holds the packets and the pin to the goldens in `tests/fixtures/method`, whose provenance file names the marketplace commit they were made from. The seventeen read tools, their schemas and their order are unchanged; the method tools follow them.
