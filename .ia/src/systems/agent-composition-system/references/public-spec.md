# Public maintained specifications and explicit bodies

The existing work-system @spec records a maintained specification. Its canonical closed schema requires meaning, title and a draft, accepted, superseded or withdrawn status. A spec may supersede at most one other spec. A decision records a choice; a playbook records a method; a contract declares boundary obligations; explicit adoption and a selected executable consumer provide enforcement. Status and admission do not establish semantic quality or execution evidence.

The author chooses a specification's contents, decomposition and document/resource membership using the existing captured-resource and authoring APIs. work.source is a text locator, not an implicit body loader. The first-party installed native reader returns captured IA source; Markdown bodies require explicit byte-pinned capture, association and separate disclosure authority.

The neutral public-spec-fixture uses a consumer-owned anchor, exact Markdown bytes, a resource association and a fixture-only document profile. It demonstrates current capture, artifact/document membership, honest missing evidence and refused stale/digest/scope inputs through installed APIs. It does not define product vision, brief, requirements vocabulary or new lifecycle policy.
