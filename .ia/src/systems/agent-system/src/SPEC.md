# Agent execution runtime

The engine runs host-authorized profiles against a durable session store. Host callbacks own model, operation, evaluator and authority bindings. Native language declarations alone do not grant execution authority.

Every session hand-over (`start`, `advance`, `reply`, `review`, `retry`, `submitModel`, `renew` and `view`) checks the host's current grant for the authenticated caller, manifest workspace and root profile, and requires its `clearances: string[]` to contain every session label. This includes duplicate commands, no-work paths and fault recovery. Missing, malformed, throwing, expired or insufficient grants refuse with the redacted `IA-ENGINE-AUTHORITY-DENIED`. The disclosure check is bounded to 60 seconds, independent of execution deadlines, cancellation and executable-input verification. Independent review authority permits a decision, not disclosure: a reviewer also needs their own current root-profile grant and session clearance.

`OperationResult.label` and the optional final `Engine.reply` argument are opaque `string[]` labels. Reconciliation results also carry labels. The reducer conservatively inherits observed content into subsequent model output and outcomes; neither model actions nor retries remove labels. Admission gates remain the atomic in-process commit authority.

Content label ids and live grant clearances share session-system's exact 1–1024-byte UTF-8, single-line representation rules. Invalid ids refuse rather than being sanitized into a different clearance.

An optional profile execution contract `release: { policy: string }` enables the closed model action `{ type: 'release', candidate: Json }`. Before persisting this candidate the engine calls trusted `host.release(principal, grant, request)`. The request contains `sessionId`, `runId`, `policy`, `candidate` and `sources: { id, digest, label }[]`: the engine derives a conservative source from the actual journal prefix (session id and sequence, head hash and full session label), never model-supplied provenance. The host returns `{ output: Json, label: string[], policyRevision: string }`, with a nonempty revision identifying the deterministic policy used. No model judges release policy.

A successful release atomically settles its model attempt without the candidate and journals the host output, label, policy revision and source digests, completing the run. Refusal, exceptions or malformed host answers persist only a redacted refusal, never the refused candidate or host error. External submissions retain a response fingerprint for exact command idempotency, not candidate bytes. Existing source history is retained. Session and run labels remain monotonic, including on release. A release candidate is never an ordinary cleared model output or outcome.

`boundary(sessionId, principal, releaseId?)` returns only `{ output, label }` under a fresh caller grant for the root profile, workspace and returned content label; it never returns private session history. An explicit successful release can cross this boundary at its host-assigned label. Without a release, only a terminal root outcome cleared for the caller can cross; its conservative label includes the entire session. `view` remains an owner read; independent reviewers use `review` rather than gaining owner execution rights.
