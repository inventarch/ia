# Public language conformance examples

This corpus demonstrates the public vocabulary. `manifest.json` selects canonical floor/schema inputs and explicit public system declarations; it does not discover additional authored records. `contracts/` preserves word/schema identities and consent semantics while supplying minimal local stewards and public requirements. `records/` contains original examples, not default design recommendations.

`tools/native/public-language.ts` compiles exactly that source set, validates schemas/system ownership, resolves relationships and compiles the example harness through the generic composition compiler with an independently supplied catalog. No model, account, marketplace or specialized quality/architecture evaluator is invoked. `tools/native/language-base.ts` separately selects the floor, declarations, schemas and language distribution root to generate the CLI's bundled language archive. Its package version is selected independently by examples/public-language/versions.json; the other example records are excluded from that archive.

Changing a canonical schema changes this corpus's input. Tests refuse unknown words, missing fields, broken references, invalid composition and unavailable installed catalog contracts. Quality and architecture requirements are illustrated using contract adoption with explicit host-provided clause evaluators. An omitted evaluator remains `not-evaluated`; authored cases and observations never manufacture execution evidence.

The observation's text/id fields illustrate representation only: schema conformance does not verify timestamps, content hashes, provenance, retention transitions or external evidence existence. Specialized consumers must enforce those contracts when their operations are selected. This prevents private retention/assessment policy from becoming an implicit language requirement.
